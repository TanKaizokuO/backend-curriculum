# Mission: Backend Development

## Why

Get hired as a backend (or full-stack) engineer. I can already program — I know Python
well — but I have never built a server, and that gap is the thing standing between me and
the job. I need to go from "writes Python" to "ships and operates HTTP services that other
people depend on."

## Success looks like

- I can build a real HTTP API from scratch — routing, validation, auth, errors — without a tutorial open.
- I can design a normalised relational schema, write the SQL, and explain why a given query is slow.
- I have 2–3 deployed projects on a public URL, with a README a reviewer can follow, that I can defend line by line in an interview.
- I can answer the standard backend interview questions from understanding rather than memorisation: what happens when you type a URL, ACID, indexes, N+1, caching, JWT vs sessions, horizontal vs vertical scaling.
- I can read an unfamiliar backend codebase and find where a request enters and where it touches the database.

## Constraints

- **~14–15 hours per week.** Enough for a lesson plus a substantial build task in each session.
- **Anchor language: Python** (already fluent) with **FastAPI** as the primary framework.
- **TypeScript is layered in deliberately, not first.** Rusty JS. See [LR-0001](./learning-records/0001-language-anchor-python-first.md) for the evidence behind this split.
- Employer-legible output matters: every phase must end in something linkable on a CV or GitHub profile.

## Out of scope

- Go, Rust, Java, C#, PHP, Ruby. Third languages before the first job is a distraction.
- Kubernetes and heavy DevOps. Deployment yes; cluster operations no.
- Machine learning / data engineering, despite the Python overlap. This is a web-backend mission.
- Frontend beyond the minimum needed to make a full-stack project demonstrable.
