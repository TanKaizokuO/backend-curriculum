Types and Coercion

  • 1. What are the primitive types in JavaScript?

    JavaScript has seven primitive types: string, number, boolean, null, undefined, symbol and bigint. A primitive holds one immutable value directly in the variable. Every other value is an object, and the variable holds only a reference to that object. Two objects with the same contents are still two different references.

  • 2. Why does typeof null return "object"?

    The first JavaScript engine stored a type tag in the low bits of each value, and the tag for an object was 0. The machine representation of null was the null pointer, so its tag was 0 too. The result is a bug from 1995. A fix breaks old code, so the standard keeps the behaviour.

  • 3. What is the difference between == and ===?

    The === operator compares the type and the value, and it converts nothing. The == operator runs the abstract equality algorithm, so it converts operands of different types first. For example "1" == 1 is true, but "1" === 1 is false. Use === by default, and use x == null only as a short test for null or undefined.

  • 4. Why is NaN === NaN false, and how do you test for NaN?

    IEEE 754 defines NaN as not equal to any value, including itself. The === operator follows that rule, so the comparison gives false. Use Number.isNaN(x), because it checks the type and the value without a conversion. The global isNaN converts the argument first, so isNaN("abc") also returns true.

  • 5. What is the difference between null and undefined?

    undefined means that the engine found no value: an unassigned variable, a missing argument or a missing property gives undefined. null means that a programmer set an empty value on purpose. typeof undefined is "undefined", but typeof null is "object". A default parameter applies to undefined only, not to null.

  • 6. Which values are falsy in JavaScript?

    JavaScript treats eight values as falsy: false, 0, -0, 0n, "", null, undefined and NaN. Every other value is truthy, and that group includes [], {} and the string "0". A truthiness test therefore hides the difference between the number zero and a missing value. Test the exact value when zero or an empty string is valid input.

  • 7. How can a primitive string have methods?

    The engine boxes the primitive: it creates a temporary String wrapper object, reads the method from String.prototype, then discards the wrapper. A property that you write on that wrapper disappears at once, so s.x = 1 loses the value. Numbers and booleans follow the same rule. Never build wrappers with new String(), because such an object is truthy even for an empty string.

  • 8. How does Object.is differ from ===?

    Object.is implements the SameValue algorithm and changes two cases. It reports Object.is(NaN, NaN) as true, and it reports Object.is(0, -0) as false. For all other pairs the result matches ===. React and other libraries use this algorithm for state comparisons.

  • 9. Why is 0.1 + 0.2 not exactly 0.3?

    A JavaScript number is a 64-bit IEEE 754 binary float. The fractions 0.1 and 0.2 have no exact binary form, so the engine stores the nearest representable values. The sum of those approximations prints as 0.30000000000000004. Compare with a small tolerance, scale the values to integers, or use BigInt for money.

  • 10. What is a Symbol and when do you use one?

    A symbol is a unique primitive, and two symbols with the same description are never equal. You use a symbol as a property key when you need a key that no other code can collide with. A symbol key stays out of Object.keys, for...in and JSON.stringify. Well-known symbols such as Symbol.iterator connect your object to a language protocol.

Scope, Closures and Hoisting

  • 11. What is the difference between var, let and const?

    var declares a function-scoped variable, so a pair of braces does not limit it. let and const declare block-scoped variables. You can reassign a let binding, but a second assignment to a const binding throws a TypeError. const protects the binding only, so you can still change the properties of a const object.

  • 12. What is the temporal dead zone?

    The engine creates the let and const bindings at the start of the block but leaves them uninitialised. The temporal dead zone is the region between the start of the block and the declaration line. A read in that region throws a ReferenceError. The rule turns a silent undefined from var into a clear error.

  • 13. How does function scope differ from block scope?

    A function scope covers the whole function body, so a var inside an if block stays visible after the block ends. A block scope covers one pair of braces, and let and const respect it. Block scope gives each loop iteration a separate binding. It also keeps a temporary variable out of the rest of the function.

  • 14. What is hoisting?

    The engine scans each scope before it runs the code and registers every declaration. A function declaration becomes available with its full body, so an early call works. A var declaration also moves to the top but starts with the value undefined. A let, a const and a class stay in the temporal dead zone until the engine reaches the line.

  • 15. What is a closure?

    A closure is a function together with the scope where you defined it. The inner function keeps a reference to the outer variables, so those variables stay alive after the outer function returns. A counter factory uses this behaviour to hold private state. Closures also support module patterns, event handlers and memoisation caches.

  • 16. What is an IIFE and why did developers use it?

    An immediately invoked function expression runs at once, for example (function () { ... })();. Before ES6 it gave the only reliable private scope, so a library hid its helpers inside one. It also created a fresh scope for each loop iteration. Modules and block-scoped let now cover these needs.

  • 17. Why do three timers in a var loop print the same number?

    A var loop variable has one binding for the whole function, and every callback reads that one binding. The timers run after the loop ends, so each one sees the final value 3. A let loop variable gets a new binding for each iteration, so the timers print 0, 1 and 2. The old fix passed the current value into an IIFE.

  • 18. How does module scope differ from global scope?

    Each ES module has a private top-level scope, so a top-level const stays hidden until you export it. A classic script shares the single global scope, and two scripts can overwrite each other. Module code runs in strict mode automatically, and top-level this is undefined. The loader evaluates each module once and caches the namespace.

  • 19. What is variable shadowing?

    Shadowing happens when an inner scope declares a name that already exists in an outer scope. The inner binding hides the outer one for the whole inner block. A shadowed parameter in a long function confuses readers and hides bugs. A let that shadows a parameter in the same function body is a SyntaxError.

  • 20. How can a closure cause a memory leak?

    The garbage collector frees an object when no reachable reference points to it. A closure keeps its variable environment reachable, so one small callback can hold a large array or a detached DOM node. The memory stays in use until you drop the last reference to the callback. Remove the listener, clear the timer, or set the reference to null.

Functions and this

  • 21. What is the difference between call, apply and bind?

    All three set the this value of a function. call invokes the function at once with separate arguments, and apply invokes it at once with an array of arguments. bind invokes nothing and returns a new function with a permanent receiver and optional preset arguments. A later call on a bound function cannot change that receiver.

  • 22. How does this work in an arrow function?

    An arrow function has no this binding of its own. It reads this from the enclosing lexical scope, so a callback inside a method keeps the method receiver. An arrow function is therefore wrong for an object method that needs the object and for a constructor. It also has no arguments object and no super.

  • 23. How do default parameters behave?

    A default parameter supplies a value when the argument is undefined. The engine keeps null, 0 and "", so the default does not apply to them. The default expression runs at call time, so function f(list = []) creates a new array for each call. A later parameter can read an earlier one, for example function f(a, b = a * 2).

  • 24. What is the difference between rest parameters and the arguments object?

    A rest parameter ...args collects the remaining arguments into a real array, so map and filter work directly. The arguments object is array-like: it has length and numeric keys but no array methods. An arrow function has no arguments object at all. Prefer the rest parameter, because it states the intent in the signature.

  • 25. What is currying?

    Currying converts a function of several arguments into a chain of functions of one argument, so add(1, 2) becomes add(1)(2). Each call returns a closure that stores the argument it received. Currying builds a specialised function from a general one, for example a logger with a fixed level. Partial application is the related idea, and bind performs it.

  • 26. What is a higher-order function?

    A higher-order function takes a function as an argument, returns a function, or does both. map, filter, setTimeout and addEventListener are common examples. The pattern separates the loop mechanism from the operation on each item. It also builds decorators such as a retry wrapper or a rate limiter.

  • 27. What makes a function pure?

    A pure function returns the same output for the same input and changes nothing outside itself. It reads no mutable global state and it writes no DOM node, no file and no argument object. Pure functions are easy to test, safe to cache and safe to run in any order. React expects pure render functions for these reasons.

  • 28. What limits recursion depth in JavaScript?

    Each call pushes a frame on the call stack, and the stack has a fixed size. Deep recursion therefore throws a RangeError about the maximum call stack size, often near ten thousand frames. The exact limit depends on the frame size and on the engine. Rewrite the algorithm as a loop, use an explicit stack, or split the work across tasks, because only Safari implements proper tail calls.

  • 29. What is method borrowing?

    Method borrowing calls a method of one object on a different object. Array.prototype.slice.call(arguments) converts an array-like value into a real array. Object.prototype.toString.call(v) returns a precise tag such as "[object Date]". The technique works because a method reads only the properties of its receiver.

  • 30. What do fn.length and fn.name report?

    fn.length gives the number of declared parameters before the first default parameter or rest parameter. fn.name gives the function name, and the engine infers it from the variable for an anonymous function expression. A curry helper reads length to decide the arity. Both properties are configurable but not writable, so Object.defineProperty changes them.

Objects, Prototypes and Classes

  • 31. What is the prototype chain?

    Every object holds an internal link to another object, its prototype. A property read that fails on the object continues to the prototype, then to the next prototype, until the chain reaches null. This lookup gives JavaScript its inheritance. A write never follows the chain; it creates the property on the object itself.

  • 32. What is the difference between __proto__ and prototype?

    prototype is a property of a constructor function, and it holds the object that becomes the prototype of each instance. __proto__ is an accessor on any object, and it points to the prototype of that object. So new Dog().__proto__ === Dog.prototype is true. Use Object.getPrototypeOf in new code, because __proto__ is a legacy feature.

  • 33. What does Object.create do?

    Object.create(proto) builds a new object with the given prototype and calls no constructor. Object.create(null) builds an object with no prototype, which makes a safe dictionary without toString and without a prototype pollution path. A second argument accepts property descriptors. The method shows that JavaScript links objects to objects, not classes to classes.

  • 34. What are the steps of the new operator?

    new creates an empty object and sets its prototype to the prototype property of the function. It calls the function with this bound to that object. It returns the new object, unless the function returns a different object explicitly. A call without new in strict mode leaves this as undefined and throws on the first property write.

  • 35. How does instanceof work and when does it fail?

    a instanceof B walks the prototype chain of a and looks for the object B.prototype. It therefore reports inherited relations, not the exact constructor. The check fails across an iframe or a worker, because each realm has separate built-in prototypes. Use Array.isArray or Object.prototype.toString for a cross-realm test.

  • 36. What does super do in a class?

    extends links the prototype of the child class to the parent class. super(...) calls the parent constructor, and a derived constructor must call it before any use of this. super.method() calls the parent version of an overridden method. A class body always runs in strict mode, and the methods are non-enumerable.

  • 37. What are static members and private # fields?

    A static member belongs to the class object, so you call Counter.reset() and not instance.reset(). A field with a # prefix is truly private: only code inside the class body reads it, and bracket access cannot reach it. An access from outside is a SyntaxError at parse time. The expression #id in obj tests for the brand without an exception.

  • 38. When do you use getters and setters?

    A getter runs a function when code reads the property, and a setter runs when code writes it. They add validation or a computed value without a change at the call sites. Keep the work small, because a reader expects the cost of a plain property read. A property with a setter but no getter always reads as undefined.

  • 39. What is a property descriptor?

    Each property carries a descriptor with value, writable, enumerable and configurable, or with get and set. A normal assignment sets all three flags to true, but Object.defineProperty defaults each flag to false. A non-enumerable property stays out of Object.keys and for...in. A non-configurable property blocks a later delete and a later redefinition.

  • 40. What is a mixin?

    A mixin adds a set of methods to a class or an object without a parent-child relation. One form copies the methods with Object.assign(Target.prototype, behaviour). Another form is a function that takes a base class and returns a subclass, so the mixin joins the prototype chain. Mixins pass the single-inheritance limit, but they hide the source of a method.

Arrays and Iteration

  • 41. How do map, filter and reduce differ?

    map returns a new array with one result for each item, so the length stays the same. filter returns a new array with the items that pass a test. reduce folds the array into one value through an accumulator, and an empty array without an initial value throws a TypeError. None of the three methods changes the source array.

  • 42. When do you prefer for...of over forEach?

    forEach calls a function for each item, and break or continue cannot stop it. for...of is a loop statement, so break, continue, return and await all work inside it. forEach also skips holes in a sparse array. Choose for...of for asynchronous work or for an early exit.

  • 43. What is a sparse array?

    A sparse array has holes, and [1, , 3], new Array(3) or a write past the end creates one. A hole differs from undefined, because 1 in arr returns false. Older methods such as forEach and map skip holes but keep them in the result. Array.from and the spread syntax convert each hole into undefined.

  • 44. Which array methods mutate the array?

    push, pop, shift, unshift, splice, sort, reverse and fill change the array in place. slice, concat, map and filter return a new array. A mutation of shared state breaks React state checks and any code that compares references. Modern engines add toSorted, toReversed, toSpliced and with for copies.

  • 45. Why does [1, 5, 10].sort() give [1, 10, 5]?

    The default sort converts each item to a string and compares the strings, and "10" comes before "5". Pass a comparator such as (a, b) => a - b for numbers. The comparator must return a negative number, zero or a positive number, and it must stay consistent for every pair. The specification requires a stable sort, so equal items keep their original order.

  • 46. What do flat and flatMap do?

    flat(depth) returns a new array with the nested arrays unpacked to the given depth, and the default depth is one. flat(Infinity) unpacks every level. flatMap maps each item and then flattens one level, so the callback returns zero, one or many items. flatMap therefore replaces a map plus a filter in one pass.

  • 47. What is the difference between the spread syntax and concat?

    Both build a new array and leave the sources unchanged. concat accepts arrays and single values, and it unpacks only array arguments one level deep. The spread syntax works on any iterable, so it also accepts a Set, a string or a generator. concat is often faster for two large arrays, because the engine copies in bulk.

  • 48. What is an array-like object?

    An array-like object has a length property and numeric keys but no array methods. The arguments object, a NodeList and an HTMLCollection are common examples. Convert with Array.from(x), or with [...x] when the value is iterable. Array.from also accepts a map function and handles a non-iterable array-like value.

  • 49. What is the iterator protocol?

    An iterable is an object with a Symbol.iterator method. That method returns an iterator, and the iterator has a next() method that returns { value, done }. for...of, the spread syntax and array destructuring all use this protocol. You can add the method to your own class and join all three features.

  • 50. What is a generator function?

    A generator function uses function* and returns an iterator. Each yield pauses the function and gives a value back, and the next next() call continues from that point with the local state intact. Generators produce lazy or infinite sequences without a large array in memory. next(value) also sends a value into the generator, so the communication runs in two directions.

Asynchronous JavaScript

  • 51. What is callback hell?

    A callback is a function that you pass to another function for a later call. Nested callbacks create deep indentation, and each level needs a separate error branch. The shape makes the order of operations hard to read and the errors easy to drop. Promises and async/await express the same logic in a flat sequence.

  • 52. What states does a promise have?

    A promise starts in the pending state. It moves once to fulfilled with a value, or once to rejected with a reason, and no later call changes the result. The word settled covers both end states. A handler that you attach after the settlement still runs, because the promise stores the result.

  • 53. How do then, catch and finally differ?

    then registers a handler for the value and returns a new promise, so a chain works. catch(fn) is short for then(undefined, fn) and it handles a rejection from any earlier step in the chain. finally runs for both outcomes and passes the original result through, so it suits cleanup. A value that you return inside then becomes the value of the next promise.

  • 54. Compare Promise.all, allSettled, race and any.

    Promise.all waits for every promise but rejects at the first rejection. Promise.allSettled always waits for every promise and returns one status object for each input. Promise.race settles with the first result, and a rejection wins the race too. Promise.any returns the first fulfilment and rejects with an AggregateError only when every input rejects.

  • 55. What does async/await do?

    An async function always returns a promise, and a plain return value becomes a fulfilled promise. await pauses the function until the promise settles and then gives the fulfilment value. The engine does not block the thread; it schedules the rest of the function as a microtask. Only an async function body or a module top level accepts await.

  • 56. How do you handle errors with await?

    A rejected promise makes await throw, so a normal try/catch block catches the reason. A missing await in front of the call moves the rejection outside the block, and the catch never runs. A catch that logs and continues hides the failure from the caller. Rethrow a wrapped error when the caller must react to it.

  • 57. How do you run two awaited calls at the same time?

    Two await statements on separate lines run the requests one after the other, so the total time is the sum. Start both calls first, keep the promises in variables, then await them, or pass them to Promise.all. The concurrent form costs the time of the slowest request. Keep the sequential form only when the second call needs the result of the first.

  • 58. What happens on an unhandled promise rejection?

    A rejected promise with no rejection handler triggers the unhandledrejection event in the browser. Node.js prints an error and stops the process by default since version 15. The runtime reports the problem only after the microtask queue drains, so a handler in the same tick still counts. Attach the catch immediately, and add a global listener for the logs.

  • 59. What is async iteration?

    An async iterable implements Symbol.asyncIterator, and each step returns a promise. The loop for await (const chunk of stream) awaits every value in order. An async generator uses async function* and mixes await with yield. This pattern reads a paged API or a network stream without a full buffer in memory.

  • 60. What does AbortController solve?

    An AbortController exposes a signal object and an abort() method. Pass the signal to fetch, to addEventListener or to your own function, and the operation stops after the abort() call. A cancelled fetch rejects with an AbortError, so your catch must separate it from a real failure. One controller cancels many operations at the same time.

The Event Loop

  • 61. What is the call stack?

    The call stack is the list of active function frames. A call pushes a frame with the parameters and the local variables, and a return pops that frame. The engine runs one frame at a time, because JavaScript has one main thread for your code. A stack overflow error means that the frames exceed the size limit.

  • 62. How does the event loop work?

    The event loop takes one task from the task queue and runs it to completion on the main thread. A timer, an I/O callback or a DOM event places a new task in the queue. Nothing else runs until the current task returns, so a long task freezes the page. The loop drains the microtask queue after each task and then lets the browser render.

  • 63. What is the difference between a microtask and a macrotask?

    A macrotask comes from a timer, a message event or an I/O callback. A microtask comes from a promise handler, from queueMicrotask or from a mutation observer. The engine empties the whole microtask queue after the current task and before the next macrotask. A promise callback therefore runs before a setTimeout callback with a zero delay.

  • 64. What does setTimeout(fn, 0) really do?

    It does not run the function at once. It queues a macrotask, so the function waits for the current task and for every pending microtask. The browser also clamps nested timers to about four milliseconds after five levels. Use the call to give the browser a chance to render, not for exact timing.

  • 65. When do you use queueMicrotask?

    queueMicrotask(fn) puts a function on the microtask queue directly. It runs after the current synchronous code and before any timer. It is clearer than Promise.resolve().then(fn) and it allocates no promise. Keep the work small, because a microtask that queues another microtask delays rendering.

  • 66. What is requestAnimationFrame for?

    requestAnimationFrame(fn) asks the browser to call the function before the next repaint, normally sixty times each second. The browser pauses these callbacks in a hidden tab and saves battery. An animation with this API stays in step with the display and avoids a torn frame. Read layout values first and write style changes second to prevent a forced reflow.

  • 67. What is a long task and how does starvation happen?

    A task above fifty milliseconds counts as a long task, and it delays the response to input. An endless chain of microtasks starves the render step completely, because the queue must empty first. Split heavy work into chunks with setTimeout, with scheduler.yield() or with a worker. The Performance panel reports each long task with its source.

  • 68. Why does setInterval drift?

    setInterval queues each call on a fixed schedule, but a busy thread delays the callback. The lateness accumulates, and two callbacks can also arrive back to back after a block. A recursive setTimeout guarantees a gap between the end of one run and the start of the next. For a precise clock, read Date.now() and correct the next delay.

  • 69. What counts as blocking code in the browser?

    A long synchronous loop, a huge JSON.parse, a synchronous XHR and an alert call all hold the main thread. The page then ignores clicks, the animations stop and the browser may show the unresponsive page dialog. Move the computation to a worker or split it across several tasks. Measure the duration first, because the limit for a smooth frame is about sixteen milliseconds.

  • 70. What is a Web Worker?

    A worker runs a script on a separate thread with its own global scope. It has no access to the DOM or to window, and it talks to the page through postMessage. The structured clone algorithm copies each message, and a transferable object such as an ArrayBuffer moves without a copy. Use a worker for parsing, image work or cryptography.

Modules, Tooling and Modern Syntax

  • 71. What is the difference between ESM and CommonJS?

    ESM uses import and export, and the loader resolves the bindings statically before evaluation. CommonJS uses require and module.exports, and it resolves at run time. An ESM import is a live binding to the exported variable, but require copies the value at that moment. ESM code is always strict, and the loader works asynchronously.

  • 72. When do you use a dynamic import()?

    A static import stays at the top level, and the bundler puts the module in the initial graph. import() returns a promise, so you call it inside a condition, a route handler or an event listener. The bundler moves that module into a separate chunk and loads it on demand. Use it for a heavy chart library, a rare dialog or a route.

  • 73. What is tree shaking and what blocks it?

    Tree shaking removes exports that no module imports. It needs the static structure of ESM, so a bundler cannot analyse a conditional require. A side effect in the module body blocks the removal, and the sideEffects field in package.json tells the bundler that a file is safe. Named exports shake better than one large default object.

  • 74. Which do you prefer: named exports or default exports?

    A named export keeps one exact name, so a typo becomes a build error and a rename tool finds every use. A default export accepts any local name at the import site, and the names drift across the codebase. Named exports also help tree shaking and the auto-import feature of the editor. Use a default export only when the module has one clear subject.

  • 75. What happens with a circular import?

    A circular import happens when module A imports B and B imports A. The loader marks a module as in progress, so the second import receives a partial namespace. A function call later works, because the binding is live, but a top-level read gets undefined or throws for a const. Move the shared part into a third module and break the cycle.

  • 76. How does destructuring work?

    Destructuring reads values out of an object or an array into variables in one statement. Object destructuring matches by key, and array destructuring matches by position. You rename with const { a: b } = obj and add a default with = 0, and the default applies only to undefined. A destructure of null throws a TypeError, so give the parameter a default object.

  • 77. What do optional chaining and nullish coalescing add?

    a?.b gives undefined when a is null or undefined instead of a TypeError, and it stops the rest of the chain. The same syntax works for a call with fn?.() and for an index with arr?.[0]. The ?? operator returns the right side only for null or undefined, so it keeps 0 and "". That behaviour is the difference from ||, which replaces every falsy value.

  • 78. What is a tagged template literal?

    A template literal uses backticks, holds a newline directly and interpolates with the ${...} form. A tagged template puts a function name before the literal, and that function receives the static string parts and the values as separate arguments. The tag escapes HTML, builds a safe SQL fragment or formats a message. String.raw is a built-in tag that keeps the backslash sequences.

  • 79. How do you make your own class iterable?

    Add a [Symbol.iterator]() method to the class. The method must return an object with a next() method, and a generator method supplies that object for free. Your class then works with for...of, with the spread syntax and with array destructuring. Symbol.asyncIterator plays the same role for for await.

  • 80. What does strict mode change?

    "use strict" turns silent mistakes into errors. An assignment to an undeclared variable throws, a write to a read-only property throws, and duplicate parameter names are a syntax error. this is undefined in a plain function call instead of the global object. A class body and an ES module use strict mode automatically.

Browser, DOM and Events

  • 81. What are the phases of DOM event propagation?

    An event travels in three phases: capture from the window down to the target, the target phase, then bubble back up to the window. A listener runs in the bubble phase by default. Pass { capture: true } to addEventListener for the capture phase. focus, blur and scroll on an element do not bubble, but focusin does.

  • 82. What is event delegation?

    Event delegation places one listener on a common ancestor instead of one listener on each child. The handler reads event.target and finds the item with closest(). The approach saves memory and it also serves elements that you add later. Exit the handler early when the target does not match the selector.

  • 83. How does preventDefault differ from stopPropagation?

    preventDefault() cancels the default browser action, for example the form submission or the link navigation. stopPropagation() blocks the listeners on the ancestor elements, but the default action still happens. stopImmediatePropagation() also blocks the other listeners on the same element. A cancelled event sets defaultPrevented to true.

  • 84. What is a passive event listener?

    A listener with { passive: true } promises that it never calls preventDefault(). The browser therefore starts the scroll at once and waits for no JavaScript. Chrome treats a touchstart or wheel listener on the document as passive by default. A preventDefault() call inside a passive listener does nothing and logs a warning.

  • 85. Compare localStorage, sessionStorage and cookies.

    localStorage keeps data with no expiry and survives a browser restart. sessionStorage keeps data for one tab and clears it on close. Both APIs are synchronous, store strings only and offer about five megabytes for each origin. A cookie holds about four kilobytes, and the browser attaches it to each matching request, so the session token belongs there with the HttpOnly flag.

  • 86. What is the difference between a reflow and a repaint?

    A reflow recomputes the geometry of the page: the position and the size of the elements. A repaint only redraws pixels for a change such as a colour, so it costs less. A read of offsetHeight right after a style write forces a synchronous reflow, and a loop of such pairs creates layout thrashing. Group the reads, then group the writes, and animate transform and opacity because they skip layout.

  • 87. When do you use debounce and when do you use throttle?

    Debounce delays the call until the events stop for a chosen time, so a search field sends one request after the typing ends. Throttle runs the function at most once for each interval, so a scroll handler keeps a steady rate. Both helpers wrap the original function in a closure with a timer. Choose debounce for a final value and throttle for continuous feedback.

  • 88. What surprises developers about fetch and CORS?

    fetch returns a promise for a Response and rejects only for a network failure. An HTTP 404 or 500 still fulfils the promise, so you must check response.ok. The browser blocks a cross-origin read unless the server sends a matching Access-Control-Allow-Origin header. A custom header or a method such as PUT triggers an OPTIONS preflight request first.

  • 89. What is the difference between DOMContentLoaded and load?

    DOMContentLoaded fires when the parser finishes the HTML and builds the DOM tree. It waits for a synchronous script but not for images, stylesheets or iframes. load fires later, after every subresource arrives. Attach the setup code to DOMContentLoaded, or add the defer attribute to the script tag.

  • 90. How do event listeners leak memory?

    A listener holds a reference to the handler and to the whole closure scope of that handler. A detached DOM node with a listener stays in memory when other code still references the node or the handler. Call removeEventListener with the same function reference, or pass an AbortController signal and abort it in the cleanup. Take a heap snapshot and search for detached nodes.

Patterns, Errors and Performance

  • 91. What is the difference between a shallow copy and a deep copy?

    A shallow copy with the spread syntax or Object.assign duplicates the top level only, so nested objects stay shared. structuredClone(value) makes a deep copy and supports Map, Set, Date and cyclic references. The old JSON.parse(JSON.stringify(x)) trick drops functions and undefined and converts a date to a string. structuredClone throws on a function or a DOM node.

  • 92. How do you use try, catch, finally and custom errors?

    The try block holds the risky code, catch receives the thrown value and finally always runs for the cleanup. A return inside finally replaces an earlier return or throw, so avoid it. Extend Error for a custom class, set this.name and pass { cause } for the original error. A catch receives any value, so test with instanceof Error before you read message.

  • 93. How does memoisation work?

    Memoisation stores the result for each argument set in a cache, normally a Map inside a closure. A later call with the same key returns the stored value and skips the computation. The function must be pure, because a hidden dependency makes the cache wrong. Limit the cache size or use a WeakMap for object keys, because an unbounded cache leaks memory.

  • 94. What does Object.freeze guarantee?

    Object.freeze(obj) blocks new properties, deletions and writes to the existing properties. The freeze is shallow, so a nested object stays mutable and a deep freeze needs recursion. A write fails silently in sloppy mode but throws a TypeError in strict mode. Immutable updates keep reference comparisons reliable for React and for an undo history.

  • 95. When do you choose a Map or a Set over a plain object?

    A Map accepts any value as a key, including an object, but an object key is always a string or a symbol. A Map keeps the insertion order, reports size directly and inherits no keys from a prototype. A Set stores unique values and gives a fast has check instead of includes on an array. Keep a plain object for a fixed record and for JSON.

  • 96. What is a WeakMap good for?

    A WeakMap holds its keys weakly, so the garbage collector removes an entry when no other reference to the key remains. It accepts objects as keys only, and you cannot iterate it or read its size. Use it to attach private data or a cache to an object without a leak. A WeakSet gives the same property for a collection of objects.

  • 97. How do you compare two objects for equality?

    The === operator compares references, so two objects with identical contents are not equal. Compare the fields yourself, write a recursive deep-equal function, or use a tested library. A comparison of JSON.stringify output looks simple, but key order, undefined and NaN break it. In React, prefer immutable updates, because then a reference check is enough.

  • 98. What are the limits of JSON.stringify?

    JSON.stringify drops functions, undefined values and symbol keys inside an object, and it writes null for them inside an array. A Date becomes an ISO string and never returns as a date object. A cyclic reference throws a TypeError, and a BigInt throws as well. A toJSON method or the replacer argument controls the output.

  • 99. Which performance traps do you watch for in JavaScript?

    A DOM query inside a loop costs time on every iteration. A new large array for each step of a reduce turns a linear loop into a quadratic one. A closure that holds a large object keeps the memory alive and lengthens the collection pause. Measure with the Performance panel first, because a guess about the slow code is often wrong.

  • 100. What is the module pattern and how does it create a singleton?

    The module pattern wraps state in a closure and returns only the public methods, so the internal variables stay private. An ES module gives the same result, and the loader evaluates each module once, so an exported object acts as a singleton. A singleton hides a dependency and makes tests harder, because the state survives between cases. Pass the instance as a parameter when a test needs a replacement.
