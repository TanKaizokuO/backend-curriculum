100 React Interview Questions

React Fundamentals

  • 1. What problem does React solve?

    React keeps the user interface in agreement with the application state. You describe the markup for a given state, and React updates the real DOM for you. Before React, teams wrote manual DOM updates for each event, and those updates drifted out of step with the data. React removes that manual step and makes the state the single source of truth.

  • 2. What is the difference between declarative and imperative user interface code?

    Imperative code lists the steps that change the screen, such as el.classList.add('active') after a click. Declarative code states the target result, such as <Tab active={isActive} />, and the library finds the steps. React is declarative, so you only map state to output. This approach cuts the number of intermediate states that you must hold in your head.

  • 3. What is JSX and what does it compile to?

    JSX is a syntax extension that looks like HTML inside JavaScript. A compiler such as Babel or SWC transforms each tag into a function call. The modern automatic runtime produces _jsx('div', { children: 'hi' }), and the older classic runtime produces React.createElement('div', null, 'hi'). The browser never sees JSX, because the build step removes it.

  • 4. What is the difference between a React element and a React component?

    An element is a plain immutable object that describes one node, with a type, a props object and a key. A component is a function that accepts props and returns elements. You call the component once per render, and React compares the returned elements. So a component is the recipe, and an element is the description of one dish.

  • 5. What is the difference between props and state?

    Props come from the parent and stay read-only inside the child. State belongs to the component and changes through a setter such as the second value from useState. A prop change and a state change both trigger a new render. Use props for data that flows down, and use state for data that this component owns.

  • 6. What does one-way data flow mean in React?

    Data moves from a parent to a child through props only. A child never writes to the props that it receives. To send information upward, the parent passes a callback prop, and the child calls that callback. This single direction makes the source of each value easy to trace during a bug hunt.

  • 7. Why does React need a key prop in a list?

    The key gives each list item a stable identity between two renders. With a key, React matches the old element to the new element and moves the DOM node instead of a rebuild. Without a key, React falls back to the position in the array, so an insert at the front makes every later item mismatch. The key must be unique among siblings and must come from the data, such as a record id.

  • 8. What is a fragment and when do you use it?

    A fragment groups several children without an extra DOM node. You write <>...</> or <React.Fragment> for the long form. Use it when a wrapper div breaks the layout, for example inside a table row or a flex container. The long form accepts a key, so a list of pairs needs it.

  • 9. How do you render markup conditionally?

    Use a ternary expression for a choice between two branches, such as {ok ? <Pass /> : <Fail />}. Use && for a single optional branch. Take care with && and a numeric left side, because 0 renders as the text zero. React ignores null, undefined and false, so a guard clause that returns null also works.

  • 10. What is the children prop?

    React puts the content between the open tag and the close tag into props.children. A layout component renders that value in a slot, so the parent controls the content and the child controls the frame. The value can be a string, an element or an array of elements. This prop is the main tool for composition in React.

Component State and Events

  • 11. How does useState work?

    useState returns an array with the current value and a setter function. React stores the value per component instance and per hook call order. The setter schedules a new render, and the component reads the new value on the next call. The initial argument applies on the first render only, so a later change to that argument has no effect.

  • 12. When do you pass a function to a state setter?

    Pass a function when the next value depends on the previous value, for example setCount(c => c + 1). React calls your function with the latest queued value, so two increments in one handler both apply. If you write setCount(count + 1) twice, both calls read the same stale variable and the count grows by one. This pattern is the functional update form.

  • 13. What is automatic batching in React 18?

    React groups several state updates from the same event into one render pass. React 18 extends this behaviour to promises, timeouts and native event handlers. Batching cuts wasted work and prevents a half-updated screen. Call flushSync when you need a synchronous DOM update, such as a measurement before a scroll.

  • 14. Why do people say that state is a snapshot?

    Each render captures the state values as constants for that render. The event handlers inside that render close over those constants. So a handler that reads count after a setter call still sees the old number. To act on the fresh value, use the updater function or read the value in an effect after the render.

  • 15. What does it mean to lift state up?

    You move the state from a child into the closest common parent of the components that need it. The parent then passes the value down as a prop and passes a setter down as a callback. Two sibling inputs stay in step, because one owner holds the truth. Lift only as far as necessary, because a high owner re-renders a large subtree.

  • 16. What is the difference between a controlled and an uncontrolled input?

    A controlled input takes its value from React state and reports each change through onChange. An uncontrolled input keeps the value in the DOM, and you read it later through a ref or through the form data. Controlled inputs allow instant validation and formatting. Uncontrolled inputs need less code and cause fewer renders for a large form.

  • 17. How do you handle a form submit in React?

    Attach an onSubmit handler to the form element, not a click handler on the button. Call event.preventDefault() to stop the browser navigation, then read the fields and send the request. The submit event also fires for the Enter key, so keyboard users get the same path. Disable the button while the request runs to block a double submit.

  • 18. What is a synthetic event?

    React wraps the native browser event in a SyntheticEvent object with a stable cross-browser interface. React attaches one listener at the root container and dispatches events through its own tree, so per-node listeners are not needed. The wrapper exposes preventDefault, stopPropagation and a nativeEvent escape hatch. Since React 17, the pooled reuse of these objects is gone, so you may read the event asynchronously.

  • 19. What is derived state and how should you handle it?

    Derived state is a value that you can compute from existing props or state, such as a full name or a filtered list. Do not copy it into another useState, because the copy goes stale when the source changes. Compute it during the render instead, and wrap it in useMemo only when the calculation is slow. A duplicate source of truth is a common cause of inconsistent screens.

  • 20. What is lazy initial state and why does it matter?

    Pass a function to useState, as in useState(() => JSON.parse(raw)). React calls that function on the first render only, so the expensive parse never repeats. If you write useState(JSON.parse(raw)), the parse runs on every render and React discards the result. Use the lazy form for reads from localStorage and for large computed defaults.

Effects and Lifecycle

  • 21. What does useEffect do?

    useEffect runs code after React commits the render to the screen. It exists for synchronisation with systems outside React, such as a network client, a timer or a browser API. React runs the effect after the paint, so the effect never blocks the first frame. The function that you return becomes the cleanup for that effect.

  • 22. How does the dependency array control an effect?

    React compares each dependency with the previous value through Object.is. An empty array means one run after the mount. A list of values means a run whenever one of those values changes. If you omit the array, the effect runs after every render, and that choice often creates a loop.

  • 23. Why does an effect need a cleanup function?

    The cleanup stops the work that the effect started. React calls it before the next run of the same effect and once before the unmount. A subscription without a cleanup leaks memory and writes state into a component that is gone. Return a function that clears the timer, aborts the request or removes the listener.

  • 24. When do you use useLayoutEffect instead of useEffect?

    useLayoutEffect runs synchronously after the DOM mutation and before the browser paints. Use it when you must measure a node and then change the layout in the same frame, such as a tooltip position. The trade-off is a blocked paint, so heavy work in this hook makes the interface feel slow. In server rendering it does not run, and React prints a warning.

  • 25. Why does StrictMode call my component and my effect twice?

    In development, StrictMode mounts each component, unmounts it and mounts it again. It also calls the render function twice. This behaviour surfaces missing cleanups and impure render code before those bugs reach production. The double call never happens in a production build, so the correct fix is a pure render and a complete cleanup.

  • 26. How do you fetch data in an effect without a race condition?

    Two fast requests can resolve out of order, so a stale response overwrites the fresh one. Declare a local flag such as let active = true. Set it to false in the cleanup, and ignore the response when the flag is false. An AbortController gives the same guard and also cancels the request. Most teams now use a data library instead, because it solves this problem and caching together.

  • 27. Which effects do you not need?

    You do not need an effect to transform data for the render, because a plain calculation in the body is enough. You do not need an effect to reset state on a prop change, because a key on the component does that. You do not need an effect to handle a user event, because the handler is the right place. Keep effects for external systems only.

  • 28. How do you tell a mount run from an update run inside an effect?

    Use a ref as a flag: start it as true, check it inside the effect, then set it to false. The presence of this code often signals a design problem, so review it first. Frequently the correct fix is two effects with different dependencies. React gives no built-in mount-only hook other than an effect with an empty dependency array.

  • 29. What does useSyncExternalStore solve?

    It subscribes a component to a store outside React, such as a Redux store or a browser media query. You pass a subscribe function and a function that reads the current snapshot. React reads the snapshot at the correct moment, so concurrent renders never show two different values in one frame. This hook replaced the old pattern of a manual subscription in an effect.

  • 30. Which class lifecycle methods map to which hooks?

    componentDidMount maps to an effect with an empty dependency array. componentDidUpdate maps to an effect with dependencies. componentWillUnmount maps to the cleanup function. getSnapshotBeforeUpdate maps to useLayoutEffect, and componentDidCatch has no hook, so an error boundary still needs a class.

Hook Rules and Other Hooks

  • 31. What are the rules of hooks and why do they exist?

    Call hooks at the top level of a component or of another hook, never inside a condition, a loop or a nested function. Call them from React functions only. React stores hook state in an ordered list per component, and it matches each call to a slot by position. A conditional call shifts that order, so one hook reads the state of another.

  • 32. What do you use useRef for?

    useRef returns a mutable object with a current property that survives every render. A write to current never triggers a render, so it suits timer ids, previous values and instance flags. Pass the same object to the ref attribute of an element, and React puts the DOM node into current after the commit. Do not read or write a ref during the render, because the value is not part of the render output.

  • 33. When do you prefer useReducer over useState?

    Use useReducer when several values change together or when the next state depends on an action type. The reducer holds the transition rules in one pure function, so tests need no component. Dispatch also keeps a stable identity, so child components avoid a re-render from a new callback. For a single independent value, useState stays simpler.

  • 34. How does useContext work?

    You create a context with createContext, wrap a subtree in the provider, and read the value with useContext. The hook finds the closest provider above the component and returns its value. Without a provider, the hook returns the default value from the create call. A new provider value re-renders every consumer in that subtree.

  • 35. What does useMemo do?

    useMemo caches the result of a calculation between renders while the dependencies stay equal. Use it for an expensive computation or for a value that must keep a stable identity for a memoised child. The hook adds its own cost, so a cheap calculation does not deserve it. React may discard the cached value, so never treat useMemo as a semantic guarantee.

  • 36. What does useCallback do and when do you need it?

    useCallback returns the same function object between renders while the dependencies stay equal. It matters when you pass the function to a component wrapped in React.memo or into a dependency array. Without a stable identity, the child sees a new prop on every render and the memo check fails. On a plain DOM element the wrapper gives no benefit.

  • 37. What is useId for?

    useId generates a unique stable string for accessibility attributes, such as a pair of htmlFor and id. The value matches between the server render and the client render, so hydration reports no mismatch. Never use it as a key in a list, because it identifies a hook call and not a data record. One call can serve several fields through a suffix.

  • 38. What do forwardRef and useImperativeHandle do?

    forwardRef passes a ref from a parent through your component to an inner element, because a ref is not a normal prop. useImperativeHandle replaces the exposed value with a small object of methods, such as focus or scrollToTop. Together they hide the DOM node and publish a narrow interface. React 19 accepts ref as a plain prop, so new code needs forwardRef less often.

  • 39. What is the difference between useTransition and useDeferredValue?

    useTransition gives you a startTransition function and a pending flag, so you mark a state update as non-urgent. useDeferredValue takes a value and returns a version that lags behind during heavy work. Use the transition when you own the update, and use the deferred value when the value arrives as a prop. Both keep typing responsive while a large list re-renders.

  • 40. What does useOptimistic do?

    useOptimistic shows a predicted state while an asynchronous action runs. You pass the real value and a function that merges an optimistic update, then you call the setter inside the action. React shows the predicted value at once and returns to the real value when the action settles. If the action fails, the optimistic value disappears, so you must still report the error.

Rendering and Reconciliation

  • 41. What is the difference between the render phase and the commit phase?

    In the render phase React calls your components and builds a tree of elements. This phase must stay pure, and React can pause, restart or discard it. In the commit phase React applies the minimum DOM changes and then runs layout effects and passive effects. Only the commit phase touches the browser, and React never interrupts it.

  • 42. What is the virtual DOM?

    The virtual DOM is a tree of plain JavaScript objects that describes the intended output. React compares the new tree with the previous tree and computes a patch for the real DOM. Object creation costs far less than a DOM write or a layout read. The concept is a diff buffer, not a faster DOM.

  • 43. Which assumptions drive the React diff algorithm?

    React compares two trees level by level and never searches for a moved subtree across levels. If the element type differs at one position, React destroys that subtree and builds a new one. Inside a list, the key prop matches a child to its previous instance. These assumptions turn a hard tree diff into a linear pass.

  • 44. Why must a list key stay stable across renders?

    React uses the key to find the previous instance and its state. An array index changes when you insert, remove or sort, so React pairs the wrong items and moves state into the wrong row. A random key such as Math.random() forces a full rebuild on every render and destroys focus and scroll. Use a stable id from the data.

  • 45. How does reconciliation decide the identity of a component?

    Identity comes from the position in the tree, the element type and the key. React keeps the state of a component while these three stay the same. A move to a different parent counts as a different position, so the state resets. This rule explains why two branches of a ternary can share or lose state.

  • 46. What happens to state when the element type at a position changes?

    React unmounts the old component, runs its cleanups and mounts the new type with fresh state. The change from <Input /> to <textarea /> therefore clears the value. You can use this behaviour on purpose: a changed key on the same component resets its state. That trick replaces a reset effect on a prop change.

  • 47. What does React.memo do?

    React.memo wraps a component and skips the re-render while the props stay shallowly equal. It compares each prop with Object.is, so a new object, array or function breaks the check. You can pass a custom comparison function as the second argument. The wrapper helps a heavy subtree, and it wastes work on a cheap one.

  • 48. What causes a component to re-render?

    A state update in the component, a new value from a context that it reads, or a re-render of its parent. A prop change alone is not a separate cause, because the parent renders first. Hooks such as useSyncExternalStore also request a render when the external store changes. A parent render walks the children even when the props stay identical, unless a memo boundary stops it.

  • 49. Why can a context update cost performance?

    Every consumer of the context re-renders when the provider value changes, and a shallow compare does not apply. A provider value built inline, such as value={{user, setUser}}, creates a new object on every parent render. Wrap that object in useMemo, or split one large context into several small ones. For high-frequency values, an external store with a selector performs better.

  • 50. How does useMemo help referential stability?

    Objects and arrays that you create during the render get a new identity each time. A memoised child, an effect dependency or a context value then sees a change that has no meaning. useMemo keeps the same reference while the inputs stay equal, so the comparison succeeds. This use of the hook is about identity, not about calculation cost.

Custom Hooks and Composition

  • 51. When do you write a custom hook?

    Write one when two components repeat the same stateful logic, such as a debounce, a media query or a form field. A custom hook is a plain function that calls other hooks, so the rules of hooks apply to it. It hides the wiring and exposes a small result. If the logic calls no hook, write a normal utility function instead.

  • 52. Does a custom hook share state between components?

    No. Each call to the hook creates its own state, because the state lives in the calling component. Two components that call useCounter get two independent counters. To share one value, put the state in a common parent, in a context or in an external store. A custom hook shares logic only.

  • 53. What is the render prop pattern?

    The parent accepts a function as a prop, often as children, and calls it with data. The caller then decides the markup, so one component supplies behaviour for many layouts. Libraries used this pattern for mouse position and for data loaders before hooks existed. Hooks cover most of these cases with less nesting.

  • 54. What is a higher-order component?

    A higher-order component is a function that takes a component and returns a new component with extra props or behaviour, for example withRouter(Page). It was the main reuse tool in the class era. The drawbacks are a deep wrapper tree, prop name collisions and a loss of the display name. Custom hooks replace most of these wrappers today.

  • 55. What is the compound component pattern?

    A parent component and a set of child components share implicit state through a context, for example <Tabs> with <Tab> and <TabPanel>. The consumer arranges the children freely, so the markup stays readable and the props list stays short. The parent keeps the selection state and the children read it. Many design systems use this pattern for menus and accordions.

  • 56. What is prop drilling and how do you fix it?

    Prop drilling passes a value through components that do not use it, only to reach a deep child. The fixes are composition, a context, or an external store. Composition often wins: pass the finished element as children and skip the middle layers. Reach for a context when many separated components need the same value.

  • 57. What does composition over inheritance mean in React?

    React has no component inheritance, so you build variants from smaller parts and props. A Dialog component accepts a header and a footer as props or children instead of a subclass. This approach keeps the relationship explicit and avoids a fragile base class. The official documents recommend it for every specialisation case.

  • 58. How do you test a custom hook?

    Test it through a component, because a hook needs a React render. The React Testing Library gives renderHook, which mounts a small host component and returns the hook result. Wrap state updates in act so React flushes them before the assertion. Assert on the returned values and on the side effects, not on the internal hook order.

  • 59. Which naming rules apply to a hook?

    The name must start with use and continue with a camel case word, such as useOnlineStatus. The linter and the compiler detect hooks by this prefix, so a wrong name disables the checks. Do not use the prefix for a function that calls no hook. Name the hook after the problem, not after the implementation.

  • 60. What shape should a custom hook return?

    Return an array when the hook exposes two related values and the caller renames them often, as useState does. Return an object when the hook exposes three or more values, because named keys stop an order mistake. Keep the shape stable across renders, and memoise any object or function that a consumer puts in a dependency array. A clear shape also documents the hook.

State Management and Data Fetching

  • 61. When do you choose a context and when do you choose a store?

    A context suits low-frequency values such as the theme, the locale or the signed-in user. A store suits data that changes often or that many distant components read, because a store lets each component subscribe to one slice. A context re-renders every consumer on each value change. So the frequency of change, not the size of the app, drives the choice.

  • 62. What are the core ideas of Redux?

    One store holds the whole state tree. You describe an intent as a plain action object and dispatch it. A pure reducer takes the current state and the action, then returns the next state. This flow makes each change traceable and supports time-travel tools and log replay.

  • 63. What does Redux Toolkit add to Redux?

    Redux Toolkit gives configureStore, createSlice and createAsyncThunk, so the old boilerplate disappears. createSlice generates the action creators and the reducers from one object. It bundles Immer, so you write direct mutations on a draft and Immer produces an immutable result. It is now the official recommended way to write Redux.

  • 64. Why must a reducer stay pure and immutable?

    React and Redux detect a change through a reference comparison. A direct mutation keeps the same reference, so the subscribers see no change and the screen stays stale. A pure reducer also gives the same output for the same input, which makes tests and replay reliable. Return a new object with the spread syntax, or use Immer to get the copy for you.

  • 65. What is a selector and why do you memoise it?

    A selector is a function that reads one piece of data from the store state. It keeps the component free of the store shape, so a refactor touches one place. A selector that builds a new array or object returns a new reference on every call and forces a re-render. A memoised selector, from createSelector for example, caches the result while the inputs stay equal.

  • 66. How does a Zustand-style store differ from Redux?

    You create the store as a hook, and each component selects the slice that it needs, as in useStore(s => s.count). There is no provider, no action type and no reducer file, because the setter functions live inside the store. The subscription is per selector, so unrelated changes cause no render. The trade-off is a weaker audit trail than the strict action log of Redux.

  • 67. What does a server cache library such as React Query give you?

    It treats server data as a cache, not as client state. It supplies the request status, deduplication, retries, background refresh and cache invalidation from one hook. The cache key, for example ['todos', userId], identifies the entry, so two components with the same key share one request. Every value inside the key must appear there, or a stale entry serves the wrong user.

  • 68. What does stale-while-revalidate mean?

    The library returns the cached data at once and marks it stale. It then starts a background request and replaces the data when the response arrives. The user sees content with no spinner, and the screen catches up a moment later. A staleTime setting controls how long the cache counts as fresh.

  • 69. How do you implement an optimistic update?

    Write the expected result into the cache or the state before the server answers, and keep the previous value. On success, replace the guess with the server response or invalidate the key. On failure, restore the previous value and show an error message. This pattern fits a like button or a checkbox, where a failure is rare and cheap to undo.

  • 70. How do you model the loading state and the error state?

    Model one status value with the cases idle, loading, success and error, instead of separate independent booleans. Separate booleans allow impossible pairs, such as a load and an error at the same time. Render a skeleton for the load, a message with a retry action for the error, and the data for the success. An error boundary catches the render errors that a status value cannot express.

Performance

  • 71. How do you profile a React application?

    Open the Profiler tab in the React DevTools and record an interaction. The flame chart shows each committed render, its duration and the components that rendered. The ranked chart sorts the components by cost, and the settings can show why each component rendered. Measure first, because the slow component is rarely the one that you suspect.

  • 72. What is list virtualisation?

    Virtualisation renders only the rows that fit in the viewport plus a small buffer. A library such as react-window or TanStack Virtual measures the scroll offset and the row height, then it positions a small window of rows. Ten thousand rows then cost the same as twenty rows. The cost is more complex code for the row height, the scroll restore and the search in the page.

  • 73. How does code splitting work with React.lazy?

    React.lazy takes a function that returns a dynamic import() and gives you a component. The bundler puts that module in a separate chunk, and the browser fetches it on first use. Wrap the component in <Suspense fallback={...}> to show a placeholder during the fetch. Split at a route boundary or at a heavy widget, such as a chart or an editor.

  • 74. How do you keep the bundle small?

    Measure it first with a bundle analyser and find the largest modules. Replace a heavy dependency with a smaller one, for example a date utility instead of a full library. Import only the parts that you use, and confirm that the package supports tree shaking through ES modules. Move a rarely used feature into a lazy chunk.

  • 75. Why do inline objects and functions as props hurt a memoised child?

    Each render creates a new object or function, so the shallow compare in React.memo fails and the child renders again. A style object such as style={{margin: 4}} has the same effect. Hoist the constant out of the component, or wrap the value in useMemo or useCallback. For a component without a memo boundary, this concern does not apply.

  • 76. How do you handle expensive derived data?

    Compute it once during the render and wrap the calculation in useMemo with the real inputs as dependencies. Measure the calculation first with performance.now(), because a filter over one hundred rows needs no cache. Move a truly heavy job to the server or to a web worker. Never copy the result into state, because a second source of truth goes stale.

  • 77. How do images and static assets affect a React page?

    A large image often costs more than the JavaScript bundle. Serve the correct size, use a modern format such as WebP or AVIF, and set loading="lazy" for content below the fold. Always set the width and the height, so the browser reserves the space and the layout does not shift. A framework image component applies most of these steps for you.

  • 78. What is the real cost of an unstable list key?

    React unmounts and remounts each row whose key changed. The remount destroys the DOM node, the component state, the focus and the scroll position, and it runs every effect again. A form inside the list loses the typed text. So a stable key protects correctness first and performance second.

  • 79. What does the React Compiler do?

    The React Compiler analyses your components and inserts the memoisation for you. It caches the values and the JSX output, so most manual useMemo and useCallback calls become unnecessary. It relies on the rules of React, so an impure render or a mutation of a prop blocks the optimisation. The compiler runs as a build plugin and needs no change in your component code.

  • 80. Which React optimisations are usually premature?

    A React.memo wrapper on every component, a useCallback for a handler on a plain button, and a useMemo for a simple sum. Each wrapper adds a comparison, a closure and a cache entry, so the total cost can exceed the saved render. Fix the real causes first: a huge unvirtualised list, a context that changes on every keystroke, or a heavy render in a parent. Profile, change one thing, then measure again.

Routing, Forms and Side Concerns

  • 81. How do routes and nested routes work in React Router?

    You declare a route table that maps a URL path to an element, and the router renders the match for the current URL. Navigation happens through a Link component, so the browser makes no full page request. A child route renders inside the parent element at the position of <Outlet />, so the parent keeps the shared layout. The URL segments join, and /settings/profile renders the settings layout with the profile panel.

  • 82. How do you read a route parameter and a query string?

    Declare the parameter in the path as /users/:id and read it with the useParams hook. For the query string, use useSearchParams, which returns a URLSearchParams object and a setter. Every value arrives as a string, so convert a number yourself and validate it. Keep filters and the pagination state in the query string, so the user can share the link.

  • 83. How do you build a protected route?

    Wrap the private routes in a guard component that reads the authentication state. If the user is not signed in, render a <Navigate to="/login" replace /> element and save the target path in the location state. After the sign-in, send the user back to that path. This check is a convenience only, because the server must still authorise every request.

  • 84. How do you navigate in code and how do you redirect?

    Call the function from useNavigate after an event, for example navigate('/orders/42'). Pass { replace: true } when the current entry must not stay in the history, such as after a sign-in. During a render, use the <Navigate /> element instead of a navigate call, because a render must stay pure. A data router can also redirect from a loader or an action.

  • 85. What is a portal and when do you need one?

    createPortal renders children into a different DOM node, such as document.body, while the component stays in the React tree. Events still bubble through the React tree, and the context still works. Use it for a modal, a tooltip or a toast, because an ancestor with overflow: hidden or a low z-index would clip the element. The portal solves a stacking problem, not a state problem.

  • 86. What is an error boundary and what does it catch?

    An error boundary is a component with componentDidCatch or getDerivedStateFromError that renders a fallback after a render error in its subtree. It catches errors from the render phase, from the lifecycle methods and from the constructors of its children. It does not catch errors in an event handler, in an asynchronous callback or on the server. Place one boundary per major region, so one broken widget does not blank the page.

  • 87. How do you integrate a third-party widget that needs a DOM node?

    Render an empty element and attach a ref to it. Create the widget inside an effect, pass ref.current to its constructor, and destroy it in the cleanup. Let the library own that DOM subtree and never render React children into it. Sync later prop changes through the imperative API of the widget in a separate effect.

  • 88. Which accessibility basics does an interviewer expect in React?

    Every input needs a real label, through a <label htmlFor> pair with useId or through aria-label. Use semantic elements, so a button for an action and an a for a link, and add a role only when no element fits. Manage the focus for a dialog: move the focus in, trap it, and return it to the trigger on close. Keep the keyboard path complete and never remove the focus outline without a replacement.

  • 89. How do you approach internationalisation in a React app?

    Keep every user-visible string in a message catalogue and look it up by key, for example with react-i18next or FormatJS. Never build a sentence from concatenated fragments, because word order differs between languages. Use the Intl APIs for dates, numbers and plural rules. Load the catalogue for the active locale as a lazy chunk, and set the lang and dir attributes on the document.

  • 90. When is dangerouslySetInnerHTML acceptable?

    Use it only for markup that you trust or that you sanitised, for example rendered Markdown that passed through DOMPurify. React escapes normal text output, so a plain {userInput} is safe, and this prop turns that protection off. Raw user HTML allows a script injection and a stolen session. The name warns you on purpose, so treat each use as a security review item.

Server Rendering, Testing and Ecosystem

  • 91. What is the difference between CSR, SSR, SSG and ISR?

    Client-side rendering sends an empty shell, and the browser builds the page from JavaScript. Server-side rendering builds the HTML per request, so the first paint arrives earlier and crawlers see the content. Static site generation builds the HTML at build time and serves it from a CDN. Incremental static regeneration serves the static page and rebuilds it in the background after a set period.

  • 92. What is hydration and what causes a hydration mismatch?

    Hydration attaches React to server-rendered HTML and adds the event listeners without a rebuild of the DOM. A mismatch happens when the first client render differs from the server HTML, so React reports an error and may replace the markup. Common causes are Date.now(), Math.random(), a read from window or localStorage, and invalid nested tags. Move that browser-only output into an effect, or mark the element with suppressHydrationWarning.

  • 93. What are React Server Components?

    A server component renders on the server only, and React sends its output as a serialised description, not as HTML alone. Its code never enters the client bundle, so it can read a database or a secret directly. It holds no state and uses no effect, and a client component must carry the 'use client' directive. You pass serialisable props from a server component to a client component.

  • 94. What are the basics of the Next.js app router?

    A folder under app/ defines a route segment, and the special files page, layout, loading and error define its parts. A layout wraps the nested segments and keeps its state during a navigation between children. Components default to server components, so you add 'use client' only where you need state or an event. A dynamic segment uses a bracket folder name such as [id].

  • 95. How does streaming work with Suspense on the server?

    The server sends the shell HTML at once and leaves a placeholder for each suspended boundary. When the data for a boundary resolves, the server streams that chunk, and the client script swaps it into place. The user reads the header and the navigation while the slow panel still loads. renderToPipeableStream provides this behaviour, and React hydrates each boundary as it arrives.

  • 96. Which queries does the React Testing Library recommend?

    Prefer getByRole with an accessible name, because it matches the way a user and a screen reader find an element. Then use getByLabelText for form fields, and getByText for static content. Use getByTestId as a last resort only. The getBy form throws at once, queryBy returns null for an absence check, and findBy returns a promise for an asynchronous appearance.

  • 97. What does an act warning mean?

    It means that a state update happened outside the window where the test framework flushed the renders. The usual cause is an asynchronous update, such as a resolved promise, after the assertion. Fix it with await screen.findBy... or await waitFor(...) instead of a manual act wrapper. A warning after the test often signals a missing cleanup in an effect.

  • 98. How do you mock network calls in a test?

    Intercept at the network layer with Mock Service Worker, so the component keeps its real fetch code. Define handlers per endpoint and override one handler inside a test for an error case. This approach survives a change from fetch to a client library, because the test asserts on the request and the screen. A stub on the global fetch works too, but it couples the test to the transport.

  • 99. How do you type component props in TypeScript?

    Declare a type or an interface for the props and annotate the parameter, as in function Card({title}: CardProps). Use React.ReactNode for children and React.ComponentProps<'button'> to inherit the native attributes of an element. Prefer a discriminated union over several optional booleans, so the compiler rejects an impossible combination. Avoid React.FC, because it adds little and complicates the generic cases.

  • 100. Which changes from React 18 to React 19 do interviewers ask about?

    React 19 adds actions, so a form can call an async function and useActionState reports its status. New hooks arrived: useOptimistic for a predicted state and use to read a promise or a context during the render. ref became a normal prop, so forwardRef is no longer needed, and a ref callback can return a cleanup. React 19 also renders document metadata tags in place and improves the hydration error messages.
