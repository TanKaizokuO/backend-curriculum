A Server Is Bytes On A Socket (JS) Node.js net module, raw sockets, no framework, and HTTP laid bare.

Before you write JavaScript for the web, you must know what a server actually does. It is not an abstract cloud function, nor is it Express or Fastify. A server is a program that runs on a physical machine. It listens on a TCP port, reads bytes from a socket, and writes bytes back. Today you write that program by hand in JavaScript.

In this lesson, you write a TCP client that fetches a webpage. You also write a TCP server that answers HTTP requests using Node.js's net module with zero dependencies and no framework.

The one idea

The whole lesson in one sentence

An HTTP server is a TCP server that reads bytes representing an HTTP request from a socket, and writes back bytes representing a valid HTTP response before closing the connection.

Step 1 · Be the client

A web browser is an HTTP client. It opens a socket to an IP address on port 80, writes a string of bytes, and reads the response. You can do the same task with Node.js's built-in net module.

Create a directory for your code:

$ mkdir lesson_1_js && cd lesson_1_js

Create client.js with this raw client:

client.js

const net = require('net');

// Open a TCP socket to example.com on port 80 (HTTP)
const client = net.createConnection({ host: 'example.com', port: 80 }, () => {
    console.log('Connected to server!');
    
    // Write the HTTP request string. Lines must end with \r\n
    client.write(
        'GET / HTTP/1.1\r\n' +
        'Host: example.com\r\n' +
        'Connection: close\r\n' +
        '\r\n'
    );
});

// Listen for bytes returning from the socket
client.on('data', (data) => {
    // data is a Buffer; toString() decodes it as UTF-8
    console.log(data.toString());
});

client.on('end', () => {
    console.log('Connection closed by server.');
});

Run it:

$ node client.js

You should see HTTP/1.1 200 OK, headers like Content-Type: text/html, a blank line (\r\n\r\n), and the HTML body. You just performed HTTP by hand.

Step 2 · Be the server

Now you write the server side. The server listens on local port 8080. It accepts TCP connections, prints client data, and writes back an HTTP response.

server.js

const net = require('net');

const server = net.createServer((socket) => {
    console.log('Client connected from:', socket.remoteAddress, socket.remotePort);

    // Triggered when the client writes bytes to the socket
    socket.on('data', (data) => {
        console.log('--- RECEIVED REQUEST ---');
        console.log(data.toString());

        // Construct a valid HTTP/1.1 response
        const body = 'Hello, JS world!\n';
        const response =
            'HTTP/1.1 200 OK\r\n' +
            'Content-Type: text/plain; charset=utf-8\r\n' +
            `Content-Length: ${Buffer.byteLength(body)}\r\n` +
            'Connection: close\r\n' +
            '\r\n' +
            body;

        // Write bytes back to the socket and close it
        socket.write(response, () => {
            socket.end();
        });
    });
});

server.listen(8080, '127.0.0.1', () => {
    console.log('Listening on http://127.0.0.1:8080');
});

Start your server:

$ node server.js

In a second terminal, send a request using curl:

$ curl -i http://127.0.0.1:8080

Look at your server logs. The printed request is plain text — the exact string format you wrote in client.js. The browser or curl only wrote text bytes onto a TCP socket.

Node.js Buffers vs Strings

In Node.js, network operations use Buffer instances (raw chunks of memory) rather than plain JavaScript strings. Call Buffer.byteLength(body) to get the count of bytes, not characters. In UTF-8, a character like é takes 2 bytes, but "é".length returns 1. If you send character length in Content-Length instead of byte length, the client truncates the response or hangs.

Step 3 · Break it on purpose

To understand HTTP framing, you must break it.

Experiment A · Delete the blank line

In server.js, change the response to remove the blank line between headers and body: replace '\r\n\r\n' + body with '\r\n' + body. Restart the server and run curl -i http://127.0.0.1:8080.

Curl fails with an error like curl: (56) Received HTTP/0.9 when not allowed or malformed response. Because HTTP uses a blank line (\r\n\r\n) to separate headers from the body, the client parses body text as a header name and fails.

Experiment B · Delete Content-Length

Restore the blank line, but remove the Content-Length header. In server.js, comment out the Content-Length line, restart the server, and send a request with curl. What happens?

Curl works because socket.end() closes the socket. Socket closure is the third legal HTTP framing strategy. However, if you keep the socket open for multiple requests, the client hangs forever. It waits for bytes that do not arrive because it does not know where the body ends.
