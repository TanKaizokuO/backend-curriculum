A Server Without A Framework (JS) Parse the request. Route it. Answer correctly. Then hand it to something better.

In JS Lesson 1, you wrote a server that ignored what the client asked for. Every request got 200 OK and the same greeting. Today you make your JavaScript read the request, parse the headers and path, route to handler functions, and respond with correct HTTP status codes.

In this lesson, you build a server that parses the start line, extracts headers and query parameters, routes by method and path, and handles errors. You also meet the native callback contract that delegates parsing work to Node's HTTP module.

The one idea

The whole lesson in one sentence

A web framework is a standard calling convention between server engine components and your application code. When you build this convention yourself, you understand what a library like Express does for you.

Step 1 · Parse the start line

JS Lesson 1's server read socket data and threw it away. The first real task is to isolate the request line (the first line of the request) and split it into method, target, and HTTP version.

server.js — start-line parser

function parseRequestLine(raw) {
    // Convert buffer to ASCII and grab the first line
    const requestStr = raw.toString('ascii');
    const firstLine = requestStr.split('\r\n')[0];
    const parts = firstLine.split(' ');
    
    if (parts.length !== 3) {
        throw new Error(`Malformed request line: ${firstLine}`);
    }
    
    const [method, target, version] = parts;
    return { method, target, version };
}

Three things to note:

  • ASCII parsing: Start-lines and headers are defined as ASCII by spec. Request bodies can contain binary or UTF-8, but we only decode the head as ASCII.
  • Validation: If the start-line does not split into exactly three space-separated parts, the request is invalid. The server must answer 400 Bad Request instead of crashing.
  • Runtime replacement: The parsing code you write here is plumbing that Node.js or a framework does for you. Knowing this mechanism helps you debug errors.

Step 2 · Parse headers and query strings

HTTP headers follow the start-line. Each line is a Name: value pair. Header names are case-insensitive by specification (RFC 9110 §5.1). Our parser must normalise header names to lower-case on arrival.

server.js — headers and query parser

function parseHeaders(raw) {
    const requestStr = raw.toString('ascii');
    // Headers end at \r\n\r\n. Skip the first line (request line).
    const parts = requestStr.split('\r\n\r\n');
    const headerLines = parts[0].split('\r\n').slice(1);
    const headers = {};

    for (const line of headerLines) {
        if (!line) continue;
        const colonIdx = line.indexOf(':');
        if (colonIdx === -1) continue;
        const name = line.slice(0, colonIdx).trim().toLowerCase();
        const value = line.slice(colonIdx + 1).trim();
        headers[name] = value;
    }
    return headers;
}

function parseQuery(target) {
    // Parse query string using standard URL API. Require a dummy base URL.
    const parsed = new URL(target, 'http://localhost');
    const query = {};
    for (const [key, value] of parsed.searchParams.entries()) {
        query[key] = value;
    }
    return { path: parsed.pathname, query };
}
Why lower-case header names?

If a client sends Content-Length: 42, another sends content-length: 42, and a third sends CONTENT-LENGTH: 42, they are identical. Normalising to lower-case on arrival means you can check headers['content-length'] and cover all cases. Node's HTTP module and Express do this automatically.

Step 3 · Routing and status codes

Our server maps a method and path to a handler function. Store these routes in a plain JavaScript object, indexed by "METHOD PATH".

server.js — routing table

const ROUTES = {
    'GET /': (req) => {
        return { status: 200, type: 'text/plain', body: 'Welcome.\n' };
    },
    'GET /hello': (req) => {
        const name = req.query.name || 'stranger';
        return { status: 200, type: 'text/plain', body: `Hello, ${name}!\n` };
    }
};

If a client requests a path that is not registered, the server returns 404 Not Found. If the path exists but for a different method (e.g., POST /hello), the server returns 405 Method Not Allowed and must include the Allow header listing valid methods for that path (RFC 9110 §10.2.1).

Step 4 · Put it all together

Here is the complete server combining parsing, routing, correct status codes, and manual string response assembly.

server.js

const net = require('net');

function parseRequestLine(raw) {
    const firstLine = raw.toString('ascii').split('\r\n')[0];
    const parts = firstLine.split(' ');
    if (parts.length !== 3) throw new Error('Malformed');
    return { method: parts[0], target: parts[1], version: parts[2] };
}

function parseHeaders(raw) {
    const requestStr = raw.toString('ascii');
    const parts = requestStr.split('\r\n\r\n');
    const headerLines = parts[0].split('\r\n').slice(1);
    const headers = {};
    for (const line of headerLines) {
        const colon = line.indexOf(':');
        if (colon === -1) continue;
        headers[line.slice(0, colon).trim().toLowerCase()] = line.slice(colon + 1).trim();
    }
    return headers;
}

const ROUTES = {
    'GET /': () => ({ status: 200, type: 'text/plain', body: 'Welcome.\n' }),
    'GET /hello': (req) => {
        const name = req.query.name || 'stranger';
        return { status: 200, type: 'text/plain', body: `Hello, ${name}!\n` };
    }
};

const PHRASES = { 200: 'OK', 400: 'Bad Request', 404: 'Not Found', 405: 'Method Not Allowed' };

function buildResponse(status, contentType, body, extraHeaders = []) {
    const phrase = PHRASES[status] || 'Unknown';
    const headers = [
        `HTTP/1.1 ${status} ${phrase}`,
        `Content-Type: ${contentType}; charset=utf-8`,
        `Content-Length: ${Buffer.byteLength(body)}`,
        'Connection: close',
        ...extraHeaders,
        '', ''
    ];
    return Buffer.concat([Buffer.from(headers.join('\r\n'), 'ascii'), Buffer.from(body, 'utf-8')]);
}

const server = net.createServer((socket) => {
    socket.on('data', (raw) => {
        try {
            const { method, target } = parseRequestLine(raw);
            const urlObj = new URL(target, 'http://localhost');
            const path = urlObj.pathname;
            
            const query = {};
            for (const [k, v] of urlObj.searchParams) query[k] = v;

            const headers = parseHeaders(raw);
            const reqKey = `${method} ${path}`;

            if (ROUTES[reqKey]) {
                const res = ROUTES[reqKey]({ query, headers });
                socket.write(buildResponse(res.status, res.type, res.body), () => socket.end());
            } else {
                // Check if path exists under another method
                const allowed = Object.keys(ROUTES)
                    .filter(k => k.split(' ')[1] === path)
                    .map(k => k.split(' ')[0]);

                if (allowed.length > 0) {
                    socket.write(buildResponse(405, 'text/plain', 'Method Not Allowed\n', [
                        `Allow: ${allowed.join(', ')}`
                    ]), () => socket.end());
                } else {
                    socket.write(buildResponse(404, 'text/plain', 'Not Found\n'), () => socket.end());
                }
            }
        } catch (err) {
            socket.write(buildResponse(400, 'text/plain', 'Bad Request\n'), () => socket.end());
        }
    });
});

server.listen(8080, '127.0.0.1');

Practice · Run and test status codes

  1. Start the server: node server.js
  2. Test GET `/hello`: curl -i http://127.0.0.1:8080/hello?name=Alice
  3. Test 405 Method Not Allowed: curl -i -X POST http://127.0.0.1:8080/hello (Verify the Allow: GET header).
  4. Test 404: curl -i http://127.0.0.1:8080/missing

What the runtime replaces: Node.js HTTP module

In Python, WSGI defined the calling convention between web server and web application. In Node.js, the gateway contract lives in the standard library. The http module handles the TCP socket, buffer accumulation, and HTTP parsing. It provides a request/response callback contract.

demo_http.js

const http = require('http');

// This function is the callback contract
const app = (req, res) => {
    const parsedUrl = new URL(req.url, `http://${req.headers.host}`);
    
    console.log(req.method, parsedUrl.pathname);
    
    res.writeHead(200, { 'Content-Type': 'text/plain; charset=utf-8' });
    res.end(`You asked: ${req.method} ${parsedUrl.pathname}\n`);
};

const server = http.createServer(app);
server.listen(9000, () => console.log('http listener up on 9000'));
Comparison to raw socket

The demo_http.js program does not import net. It has no socket.on('data'), no \r\n\r\n string splits, and no Content-Length calculations. That is what Node's internal HTTP server does. Express, Koa, and Fastify are all built on top of this exact (req, res) listener.
