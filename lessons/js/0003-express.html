Express The framework does the plumbing. You do the thinking.

In JS Lesson 2, you wrote a server that parsed raw bytes, routed requests through a dictionary, and answered with correct status codes in 80 lines. You also met Node's native HTTP callback contract. Today you pass request parsing to a framework. Express is the standard framework for Node.js backends. In this lesson, you build a JSON API with routing, path parameters, query parameters, body parsing, validation, and status responses.

In this lesson, you build a server.js file with Express. You can send curl requests to manage bookmarks. Every feature matches the manual work from JS Lessons 1–2.

The one idea

The whole lesson in one sentence

Express is a routing and middleware framework that wraps Node's native http module, replacing manual parsing and response formatting with declarative handlers and a pipeline of request processors.

Step 0 · Install and run

Set up a Node.js project and install Express:

$ mkdir bookmarks-api-js && cd bookmarks-api-js
$ npm init -y
$ npm install express

Create server.js with a minimal hello world:

server.js — hello world

const express = require('express');
const app = express();

app.get('/', (req, res) => {
    res.json({ message: 'Hello, JS world' });
});

app.listen(8000, () => {
    console.log('Express server listening on http://127.0.0.1:8000');
});

Run it:

$ node server.js
What just happened

express() returns an application object. When you call app.listen(), Express internally calls Node's native http.createServer(app) and starts the TCP listening loop. The Express app is the request listener callback. Every incoming connection triggers it, and it pipes the request and response objects through its router.

Step 1 · Routing — decorators vs method calls

In JS Lesson 2 your routing table was an object with method-path keys:

const ROUTES = {
    'GET /': handle_index,
    'GET /hello': handle_hello,
};

Express provides helper methods for each HTTP verb: app.get(), app.post(), app.put(), app.delete(). You register a route by passing a path string and a callback handler function.

Compare to Lesson 2

Express matches the request method and path against internal routes. If the path matches with a different verb (such as POST /), Express returns 405 Method Not Allowed with an Allow header when configured. By default, it returns 404 unless a matching path with another method has a handler. The framework handles method matching and routing table lookup so you do not parse req.method and req.path manually.

Step 2 · Path parameters — route patterns

Instead of exact string matching, Express supports route patterns. You define a variable segment in a path using a colon (:name). Express parses this segment and places the extracted value in req.params.

server.js — path params

const BOOKMARKS = {};

app.get('/bookmarks/:bookmark_id', (req, res) => {
    // req.params contains route parameter matches
    const id = parseInt(req.params.bookmark_id, 10);
    
    if (isNaN(id)) {
        return res.status(400).json({ detail: 'ID must be an integer' });
    }
    
    if (!BOOKMARKS[id]) {
        return res.status(404).json({ detail: 'Bookmark not found' });
    }
    
    res.json(BOOKMARKS[id]);
});
  • Extraction: Express parses :bookmark_id from the path and attaches it as req.params.bookmark_id.
  • No auto-conversion: Unlike FastAPI (which uses Python type hints to convert strings to integers), Express provides path params as **strings**. You must call parseInt() by hand.
  • Manual validation: If a client sends /bookmarks/abc, parseInt() returns NaN. You must manually check isNaN(id) and return a 400 Bad Request response.

Step 3 · Query parameters — parsed on request

Express parses query parameters automatically and exposes them on req.query. You do not need to import url or call new URL() manually.

server.js — query params

app.get('/bookmarks', (req, res) => {
    // req.query contains parsed query string parameters
    const skip = parseInt(req.query.skip || '0', 10);
    const limit = parseInt(req.query.limit || '10', 10);

    const list = Object.values(BOOKMARKS);
    res.json(list.slice(skip, skip + limit));
});

Every query parameter arrives as a string. You must handle default fallbacks (e.g. req.query.skip || '0') and type conversions yourself.

Step 4 · Request bodies and middleware

In JS Lesson 2 you read request bodies from TCP stream buffers. In Express, you use **middleware** to parse bodies. A middleware function intercepts the request before it reaches your handler.

To accept JSON bodies, you must register the built-in JSON-parsing middleware: app.use(express.json()). Without it, req.body is undefined.

server.js — POST endpoint + body validation

app.use(express.json()); // Enables JSON body parsing

let nextId = 1;

app.post('/bookmarks', (req, res) => {
    const { url, title } = req.body;

    // Manual validation (Python/FastAPI does this automatically via Pydantic)
    if (!url || typeof url !== 'string') {
        return res.status(400).json({ detail: 'Field "url" is required and must be a string' });
    }

    const entry = { id: nextId++, url, title: title || null };
    BOOKMARKS[entry.id] = entry;

    res.status(201).json(entry);
});
Express lacks automatic schema validation

In FastAPI, declaring a Pydantic model validates the request body, formats the error response, and updates the OpenAPI docs automatically. In Express, you write validation checks by hand, or install a validation library like Zod. Without validation middleware, Express will blindly accept any JSON structure a client sends, leading to runtime crashes.

Step 5 · The documentation gap

FastAPI parses code structure and generates live interactive documentation at /docs. In Express, automatic documentation is not built in. Because JavaScript is a dynamic language without compile-time types, the framework does not know the shape of path parameters, query parameters, or request bodies without manual documentation.

To build interactive documentation in JavaScript, write Swagger comments with JSDoc or write your API with TypeScript and schema libraries such as Zod. You learn this transition when you layer TypeScript into the curriculum.

Step 6 · The complete Express app

Here is the complete bookmarks API. It handles listing, getting, creating, and deleting bookmarks using Express.

server.js

const express = require('express');
const app = express();

app.use(express.json());

// In-memory data store
const BOOKMARKS = {};
let nextId = 1;

// Get bookmarks (paginated)
app.get('/bookmarks', (req, res) => {
    const skip = parseInt(req.query.skip || '0', 10);
    const limit = parseInt(req.query.limit || '10', 10);
    
    const list = Object.values(BOOKMARKS);
    res.json(list.slice(skip, skip + limit));
});

// Get bookmark by ID
app.get('/bookmarks/:bookmark_id', (req, res) => {
    const id = parseInt(req.params.bookmark_id, 10);
    if (isNaN(id)) {
        return res.status(400).json({ detail: 'ID must be an integer' });
    }
    if (!BOOKMARKS[id]) {
        return res.status(404).json({ detail: 'Bookmark not found' });
    }
    res.json(BOOKMARKS[id]);
});

// Create bookmark
app.post('/bookmarks', (req, res) => {
    const { url, title } = req.body;
    if (!url || typeof url !== 'string') {
        return res.status(400).json({ detail: 'Field "url" is required and must be a string' });
    }
    
    const entry = { id: nextId++, url, title: title || null };
    BOOKMARKS[entry.id] = entry;
    res.status(201).json(entry);
});

// Delete bookmark
app.delete('/bookmarks/:bookmark_id', (req, res) => {
    const id = parseInt(req.params.bookmark_id, 10);
    if (isNaN(id)) {
        return res.status(400).json({ detail: 'ID must be an integer' });
    }
    if (!BOOKMARKS[id]) {
        return res.status(404).json({ detail: 'Bookmark not found' });
    }
    delete BOOKMARKS[id];
    res.status(204).send();
});

app.listen(8000, () => console.log('Server running on http://127.0.0.1:8000'));

Practice · Run and test

  1. Start the server: node server.js
  2. Create a bookmark:
    curl -i -X POST http://127.0.0.1:8000/bookmarks -H "Content-Type: application/json" -d '{"url":"https://expressjs.com", "title":"Express docs"}'
  3. List bookmarks (verify pagination):
    curl -i http://127.0.0.1:8000/bookmarks?limit=1
  4. Try bad input validation:
    curl -i -X POST http://127.0.0.1:8000/bookmarks -H "Content-Type: application/json" -d '{"title":"no url"}' (Verify status 400).
  5. Delete bookmark:
    curl -i -X DELETE http://127.0.0.1:8000/bookmarks/1 (Verify status 204).
