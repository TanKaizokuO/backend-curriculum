Deployment (JS) A deploy is one container image plus one set of environment variables.

In JS Lesson 6, you handled concurrent database writes and evaluated ORM abstractions. Today you deploy your Node.js Express API to cloud infrastructure. You containerise the application using Docker, isolate runtime configuration, implement automated database release steps, verify health check endpoints, and deploy a production service using Render Blueprints.

The whole lesson in one sentence

A production deployment packages code into an immutable container image, passes configuration through environment variables, and executes database migrations during a separate release step.

Step 1 · Observe naive deployment defects

Inspect four common deployment defects in naive/Dockerfile and naive/server.js:

  • Hardcoded local database DSN — Connecting to localhost inside a container fails because localhost points to the container itself.
  • Binding to 127.0.0.1 — Calling app.listen(8000, '127.0.0.1') limits incoming socket connections to loopback inside the container, blocking external requests. You must bind to 0.0.0.0.
  • Development reloader in production image — Running npx nodemon in production wastes RAM and spawns extra watcher processes.
  • Hardcoded credentials in image layers — Storing database passwords in ENV instructions exposes secrets in image history.

Step 2 · Implement twelve-factor configuration

Isolate runtime configuration into environment variables using config.js. Read DATABASE_URL and PORT from process.env on startup and exit immediately if required values are missing.

config.js

function loadConfig() {
  const databaseUrl = process.env.DATABASE_URL;
  if (!databaseUrl) {
    console.error('FATAL: DATABASE_URL environment variable is required.');
    process.exit(1);
  }
  return {
    databaseUrl,
    port: parseInt(process.env.PORT || '8000', 10),
    nodeEnv: process.env.NODE_ENV || 'development'
  };
}

Step 3 · Write a production Dockerfile

Build a minimal production container image using official Node.js Alpine base images and non-root execution users:

Dockerfile

FROM node:22-alpine
WORKDIR /app
USER node
COPY --chown=node:node package*.json ./
RUN npm ci --only=production
COPY --chown=node:node . .
ENV PORT=8000 NODE_ENV=production
EXPOSE 8000
CMD ["node", "server.js"]

Step 4 · Separate build, release, and run steps

Do not execute SQL database migrations inside application startup handlers or container build steps. Execute migrations during a dedicated release step using migrate.js before starting application containers.

$ node migrate.js
Applying migration: 0001_create_bookmarks.sql...
Successfully applied: 0001_create_bookmarks.sql
All migrations are up to date.

Step 5 · Implement a database health check

Add a /healthz endpoint in Express to verify database connectivity before routing user traffic:

app.get('/healthz', async (req, res) => {
  try {
    await pool.query('SELECT 1');
    res.status(200).json({ status: 'ok', env: config.nodeEnv });
  } catch (err) {
    res.status(503).json({ status: 'unhealthy', detail: err.message });
  }
});

Step 7 · Declare infrastructure with Render Blueprints

Define declarative cloud deployment specifications in render.yaml:

services:
  - type: web
    name: bookmarks-api-js
    runtime: node
    buildCommand: npm ci
    startCommand: npm start
    preDeployCommand: npm run migrate
    envVars:
      - key: DATABASE_URL
        fromDatabase:
          name: bookmarks-db-js
          property: connectionString

databases:
  - name: bookmarks-db-js
    databaseName: bookmarks
    user: learner
    plan: free

Check your understanding

1. Why must a server process bind to host address 0.0.0.0 inside a Docker container?

Correct! Binding to 127.0.0.1 limits socket access to inside the container. 0.0.0.0 binds to all network interfaces, allowing external proxy traffic.

2. When should database migrations run during deployment?

Correct! Running migrations during a separate release step ensures transactional schema updates complete before new web instances accept live traffic.
