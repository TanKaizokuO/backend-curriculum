TypeScript Crash Course Add types to JavaScript to find errors before you run the program.

You know JavaScript. But JavaScript does not check types before the program runs. TypeScript is JavaScript with static types. It finds errors while you write the code.

The whole lesson in one sentence

Define the shape of your data. The compiler checks the shape for you.

1. TypeScript Fundamentals

TypeScript is a superset of JavaScript. It adds type annotations to the language. You use the TypeScript compiler (tsc) to translate TypeScript code into standard JavaScript. You run the standard JavaScript with Node.js.

You can write explicit type annotations. When you do not write them, the compiler uses type inference. It guesses the type from the value.

You configure the compiler with a file. The name of the file is tsconfig.json.

2. Basic Types

You define basic types with these keywords:

  • string for text.
  • number for integers and floating-point numbers.
  • boolean for true or false values.
  • null and undefined for missing values.
Warning

Do not use the any type. The any type disables the type checker. If you use it, the compiler cannot find errors.

Use the unknown type when you do not know the value. You must check the type before you use an unknown value. Use the never type for a function that throws an error and never returns. Use the void type for a function that returns nothing.

You can use literal types. A literal type specifies an exact value.

let status: "active" | "inactive";
status = "active";

You can use a type assertion. A type assertion tells the compiler the type of a value. Use the as keyword for a type assertion.

3. Arrays, Tuples, and Objects

You define an array of numbers with number[]. All elements in the array must be numbers.

A tuple is an array with a fixed length and fixed types. You define a tuple with brackets.

let record: [number, string] = [1, "test"];

You define an object type with braces. You write the property names and their types.

let user: { id: number; name: string };

You make a property optional when you add a question mark. You make a property read-only when you add the readonly keyword. You cannot change a read-only property.

Use an index signature when you do not know the property names. The index signature defines the type for all keys.

let scores: { [key: string]: number };

4. Functions

You must specify the types for function parameters. You can specify the return type. The compiler can usually infer the return type.

function add(x: number, y: number): number {
  return x + y;
}

You make a parameter optional when you add a question mark. You can provide a default value for a parameter.

You use rest parameters to collect multiple arguments into an array. You define the rest parameter as an array type.

You can define a type for a function. You use an arrow syntax to define a function type. You use this to specify callback types.

You can write overloaded functions. You write multiple signatures for the same function. The compiler checks the arguments against the signatures.

5. Interfaces and Type Aliases

You use an interface to name an object type. You use a type alias to name any type.

interface User {
  id: number;
  name: string;
}

type ID = string | number;

An interface can extend another interface. You use the extends keyword. A type alias can use the & symbol to create an intersection type. Both methods combine types.

An interface and a type alias have similar behavior. You use them to create reusable type definitions. Prefer an interface for object shapes. Prefer a type alias for unions.

6. Unions and Narrowing

You use the | symbol to create a union type. A union type means the value can be one of several types.

You must narrow a union type before you use it. You write a type guard to narrow the type. The compiler analyzes your code and understands the narrower type.

  • Use typeof to check a basic type.
  • Use instanceof to check a class instance.
  • Use the in operator to check if a property exists in an object.

You can write a custom type predicate. A custom type predicate is a function that returns a boolean. It tells the compiler the specific type of the argument.

You can use a discriminated union. A discriminated union is a union of object types. Each object type has a common property. The common property is a literal type. You check the common property to narrow the type.

7. Enums and Literal Types

An enum names a set of values. You can define a numeric enum. The values are numbers. You can define a string enum. The values are strings.

enum Direction {
  Up = "UP",
  Down = "DOWN"
}

You can write a const enum. The compiler replaces a const enum with the plain value. It does not generate an object in the standard JavaScript.

You can usually use a union of literal types instead of an enum. Literal types are simpler and do not generate extra JavaScript code.

8. Generics

Generics help you write reusable code. You define a type parameter. You use the type parameter inside the function or class.

function identity<T>(arg: T): T {
  return arg;
}

You can write generic functions. You can write generic interfaces. You can write generic types.

You can define generic constraints. You use the extends keyword to limit the type parameter. The compiler enforces the constraint.

You can use multiple type parameters. You separate them with a comma.

9. Advanced Types

You use the keyof operator to get a union of the keys of a type. You use the typeof operator to get the type of a variable.

You use an indexed access type to get the type of a specific property.

type UserType = User["name"];

You can write a conditional type. A conditional type uses a ternary operator format to choose a type.

You can write a mapped type. A mapped type creates a new type. It iterates over the keys of an existing type.

You can write a template literal type. A template literal type combines string literal types.

10. Built-in Utility Types

TypeScript provides utility types to transform existing types.

  • Partial<T> makes all properties of T optional.
  • Required<T> makes all properties of T required.
  • Readonly<T> makes all properties of T read-only.
  • Pick<T, K> creates a type with only the specified keys K from T.
  • Omit<T, K> creates a type that removes the specified keys K from T.
  • Record<K, T> creates an object type. The keys have type K. The values have type T.
  • Exclude<T, U> removes the types in U from the union T.
  • Extract<T, U> selects the types in U from the union T.
  • ReturnType<T> gets the return type of a function type T.
  • Parameters<T> gets the parameter types of a function type T as a tuple.

11. Classes and OOP

You define types for the properties of a class. You define types for the constructor parameters.

You use access modifiers to control visibility. Use public for properties that anyone can access. Use private for properties that only the class can access. Use protected for properties that the class and its subclasses can access.

You can make a property read-only. You use the readonly keyword.

You can define an abstract class. An abstract class cannot be instantiated. Another class must extend it.

A class can implement an interface. The compiler checks that the class matches the interface.

12. Modules

You use the import and export keywords to share code between files. You can use default exports. You can use named exports.

You can use a type-only import. A type-only import starts with import type. The compiler removes a type-only import from the standard JavaScript.

The compiler uses module resolution to find the imported files. You configure the module resolution in tsconfig.json. Organize your project into small files. Each file is a module.

13. TypeScript with the JavaScript Ecosystem

You use npm packages in a TypeScript project. Many packages use JavaScript. They do not have types.

You install type definitions from the @types scope on npm. The DefinitelyTyped repository manages these definitions.

npm install @types/express

You can use TypeScript with Node.js and Express. You define types for the Express request and response objects.

You must define types for environment variables. You extend the ProcessEnv interface in the global namespace.

14. Async TypeScript

You use a generic type to describe a promise. A promise that resolves to a string has the type Promise<string>.

You use the async and await keywords for asynchronous code. An async function always returns a promise.

You define types for your API responses. This helps you parse the JSON data safely.

Caution

Catch errors explicitly. The error variable in a catch block has the unknown type. You must check its type before you use it.

15. TypeScript and React

You define an interface for the properties of a React component. You define an interface for the state.

You define types for DOM events. The type of a click event is React.MouseEvent.

You use generics with React hooks. You pass the type parameter to useState and useRef.

const [count, setCount] = useState<number>(0);

You can write generic components. A generic component accepts a type parameter when you render it.

16. TypeScript Configuration

You manage the project with a tsconfig.json file.

  • Set the strict flag to true. This enables all strict type checks.
  • Set the noImplicitAny flag to true. The compiler rejects variables when it cannot infer the type.
  • Set the strictNullChecks flag to true. The compiler requires you to check for null values.

You set the target property to choose the JavaScript version for the output. You set the module property to choose the module system.

Set esModuleInterop to true. It improves compatibility with CommonJS modules.

You can set sourceMap to true. The compiler creates source maps. Source maps connect the standard JavaScript to the TypeScript code. You use source maps for debugging.

17. Common Patterns and Pitfalls

Do not use the any type to silence the compiler. If you do not know the type, use unknown and narrow it later.

Handle null and undefined explicitly. The type checker finds paths where a value might be missing.

Do not use type assertions to force a type. Write proper type guards. Let the compiler infer the types.

Do not build complex type definitions if simple types solve the problem. Keep the code readable.

Read the compiler errors from top to bottom. The last line of the error usually contains the specific mismatch.

18. Practical Project: Build a TypeScript REST API

You build a REST API to combine these concepts. You set up the project with tsc --init. You configure the strict mode.

You write interfaces for your data models. You define the types for the database records.

You write a generic interface for the API response. The response contains a status code and a generic data payload.

You define the request and response types for your Express route handlers. The compiler checks that you return the correct data structure.

You write an asynchronous function to query the database. You type the return value as a promise. You catch the database errors. You check the error type and return an HTTP error.

You define the environment variables for the database connection. The compiler ensures that you read the variables safely.

You use a modular architecture. You separate the route definitions, the database queries, and the data models into different files.
