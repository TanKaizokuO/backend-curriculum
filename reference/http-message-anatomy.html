HTTP Message Anatomy Compressed reference. Normative claims cite RFC 9110 (HTTP Semantics, June 2022, STD 97) by section.

Message shape

Request and response are the same four-part structure. Only the first line differs. Every line terminates with \r\n.

REQUEST                              RESPONSE
GET /users/7?full=1 HTTP/1.1         HTTP/1.1 200 OK
└method └target      └version        └version └code └reason

Host: api.example.com                Content-Type: application/json
Accept: application/json             Content-Length: 27
Authorization: Bearer eyJhbG...      Cache-Control: no-store
└─ headers ────────────────┘         └─ headers ──────────────┘
                                     ← blank line: THE separator →

└─ body (optional) ────────┘        {"id": 7, "name": "Ada"}
Three rules that cause most bugs
  • Line endings are CRLF (\r\n), never bare \n.
  • The blank line ends the headers. Omit it and the client parses your body as headers.
  • The body needs framing — see below. Omit it and the client hangs.

Body framing — the three legal options

TCP is a byte stream with no message boundaries. The receiver must be told where the body stops. There are exactly three ways, and you must use one.

MechanismLooks likeUse when
Content-Length Content-Length: 27 You know the size up front. Almost every JSON API response.
Chunked encoding Transfer-Encoding: chunked, then hex-length-prefixed chunks Streaming, or the size is unknown when headers are sent.
Connection close Connection: close, then hang up Legacy fallback. Responses only — a request cannot use it.

Give none of the three and the client blocks forever with no error. "The request just hangs" is nearly always a framing bug. Note the asymmetry: a client cannot signal end-of-body by closing, since it still needs the socket to read the reply — which is why an unframed request body gets 411 Length Required.

Methods

Safe = read-only in intent; automated tools may call it freely (§9.2.1). Idempotent = N identical requests have the same effect as one, so a client or proxy may retry after a dropped connection (§9.2.2).

MethodSafeIdempotentMeaning
GETyesyesRetrieve the resource.
HEADyesyesLike GET, headers only, no body.
OPTIONSyesyesAsk what is permitted. The CORS preflight.
TRACEyesyesLoopback diagnostic. Usually disabled.
PUTnoyesReplace the resource entirely with the body.
DELETEnoyesRemove the resource.
POSTnonoProcess the body per resource-specific semantics.
PATCHnonoPartial modification. Defined in RFC 5789, not 9110.
CONNECTnonoOpen a tunnel. How HTTPS traverses a proxy.
Interview trap

Idempotent is not the same as "no side effects." DELETE changes the world, yet is idempotent: after the first call the resource is gone, and repeats leave it gone. POST /orders is not, because each call creates another order. This is exactly why a proxy must not auto-retry a POST (§9.2.2) and why "retry on timeout" is safe for PUT but a duplicate-charge bug for POST.

Status codes

Five classes (§15). The first digit is the whole contract — a client that understands only the class can still behave correctly.

401 vs 403 is asked in interviews constantly. RFC 9110 §15.5.2: 401 means the request "lacks valid authentication credentials" — who are you? 403 means the server understood who you are and is refusing anyway — I know, and no. The name "Unauthorized" on 401 is a historical mistake; do not let it mislead you.

Python recipes

Minimum viable response

body = b'{"ok": true}'
head = (
    "HTTP/1.1 200 OK\r\n"
    "Content-Type: application/json\r\n"
    f"Content-Length: {len(body)}\r\n"
    "Connection: close\r\n"
    "\r\n"
).encode("ascii")
conn.sendall(head + body)

Read until the headers end

recv() returns whatever has arrived, not a whole message. Loop.

buf = b""
while b"\r\n\r\n" not in buf:
    chunk = conn.recv(4096)
    if not chunk:                 # peer hung up mid-request
        break
    buf += chunk
head, _, rest = buf.partition(b"\r\n\r\n")

Parse a start-line

start, *header_lines = head.decode("latin-1").split("\r\n")
method, target, version = start.split(" ")
headers = {}
for line in header_lines:
    name, _, value = line.partition(":")
    headers[name.lower()] = value.strip()   # names are case-insensitive
