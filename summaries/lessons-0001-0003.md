# Lessons 1–3 Comprehensive Summary

## Lesson 1 — A Server Is Bytes On A Socket

### Core Mental Model
An HTTP server is a socket program that accepts a TCP connection, reads structured text off the socket, and writes back structured text according to an agreed specification. Frameworks and abstractions (routing, ORMs, JSON parsing) add developer convenience on top of this basic socket loop.

### HTTP/1.1 Byte Anatomy
1. **Request Message**:
   - **Start-line (Request-line)**: `METHOD target HTTP/version` (e.g., `GET /hello?name=world HTTP/1.1`)
   - **Headers**: `Name: Value` lines (e.g., `Host: 127.0.0.1:8080`, `User-Agent: curl/8.5.0`)
   - **Separator**: A mandatory blank line (`\r\n\r\n`) separating headers from the body.
   - **Body**: Optional payload bytes.
2. **Response Message**:
   - **Start-line (Status-line)**: `HTTP/version status-code reason-phrase` (e.g., `HTTP/1.1 200 OK`)
   - **Headers**: Metadata (e.g., `Content-Type: text/plain; charset=utf-8`, `Content-Length: 21`)
   - **Separator**: A mandatory blank line (`\r\n\r\n`).
   - **Body**: Response payload.
3. **CRLF Requirement**: Every line ending must be `\r\n` (carriage return + line feed), encoded as ASCII.

### Framing & Body Termination Strategies
Because TCP is an unstructured byte stream without native message boundaries, an HTTP client requires a framing strategy to determine where a response body ends. There are three legal strategies:
1. **`Content-Length` Header**: Explicit integer specifying exact body byte count.
2. **Chunked Transfer Encoding**: `Transfer-Encoding: chunked` sends length-prefixed hex byte chunks.
3. **Closing the Connection**: The server sends `Connection: close` and closes the TCP socket when done.

*Framing Bug*: Omitting all three framing mechanisms over a persistent TCP connection causes the client socket read (`recv`) to hang indefinitely.

### Protocol Rules & Socket Server Plumbing
- **`Host:` Header**: Mandatory in HTTP/1.1 for virtual hosting (mapping one IP address to multiple domains). Omission triggers a `400 Bad Request`.
- **Low-Level Socket Setup**:
  - Client: `socket.create_connection(("example.com", 80))`, send bytes, loop `sock.recv(4096)`.
  - Server: `socket.socket()`, `setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)`, `bind()`, `listen()`, `accept()`.
- **Purposeful Failure Experiments**:
  - *Deleting the blank line (`\r\n` separator)*: `curl` parses response body text as a header name and fails with `curl: (8) Header without colon`.
  - *Deleting `Content-Length` with persistent connection*: `curl` blocks indefinitely waiting for bytes.

## Lesson 2 — A Server Without A Framework

### Core Mental Model
A web framework is a standard calling convention between an HTTP server (which handles socket connections and byte parsing) and application code (which handles business logic).

### Manual HTTP Parsing & Routing Engine
1. **Request Line Parsing**:
   - Decode ASCII, split by CRLF (`\r\n`) to extract the start-line.
   - Split start-line by spaces into exactly 3 parts (`method`, `target`, `version`). Anything else is malformed and must return `400 Bad Request`.
2. **Header Parsing**:
   - Parse `Name: Value` lines into a lower-cased dictionary. RFC 9110 specifies header names are case-insensitive; lower-casing on arrival normalises lookups.
3. **Query Parameter Extraction**:
   - Use `urllib.parse.urlparse` and `parse_qs` to extract URL path and convert query string `?key=val` into a dict of key-to-list mappings.
4. **Routing Table**:
   - Map `(method, path)` tuples to specific handler functions.
   - Separate route matching enables distinguishing between missing resources (`404 Not Found`) and unsupported HTTP methods for an existing route (`405 Method Not Allowed`).
5. **Status Codes & RFC Compliance**:
   - `200 OK`: Successful execution.
   - `400 Bad Request`: Malformed HTTP request line syntax.
   - `404 Not Found`: Target path does not exist in routing table.
   - `405 Method Not Allowed`: Target path exists, but not for the requested method. Must include an `Allow` header listing permitted methods (RFC 9110 §10.2.1).

### Python Web Calling Conventions (WSGI vs ASGI)
- **WSGI (PEP 3333)**:
  - Synchronous calling contract: `application(environ, start_response)`.
  - `environ`: Dictionary containing request data (`REQUEST_METHOD`, `PATH_INFO`, `QUERY_STRING`, `HTTP_*` headers).
  - `start_response(status, headers)`: Callback to set response line and headers. Returns iterable of body byte chunks.
  - Powering: Flask, Django, Gunicorn, `wsgiref`.
- **ASGI (v3.0 Spec)**:
  - Asynchronous calling contract: `async application(scope, receive, send)`.
  - Handles async I/O, WebSockets, and HTTP/2.
  - Powering: FastAPI, Starlette, Uvicorn.

### Architecture Stack Layers
```
[Client] -> [OS/Kernel: TCP] -> [Server: Uvicorn/Sockets] -> [ASGI/WSGI Interface] -> [Framework] -> [Handler Code]
```

## Lesson 3 — FastAPI

### Core Mental Model
FastAPI is an ASGI application framework built on Starlette and Pydantic. It leverages standard Python type annotations to replace manual plumbing with automated routing, parameter extraction/validation, JSON request body parsing, response serialisation, error handling, and OpenAPI documentation.

### Core Features & Automated Mechanics
1. **Decorator-Based Routing**:
   - `@app.get()`, `@app.post()`, `@app.delete()`, `@app.put()` register path operations into Starlette's route table.
2. **Path Parameter Conversion & Validation**:
   - URL template segments like `/bookmarks/{bookmark_id}` with function annotations (`bookmark_id: int`) automatically extract, type-coerce string path components to `int`, and validate inputs.
3. **Query Parameter Handling**:
   - Function parameters not matching path placeholders default to query parameters (e.g., `skip: int = 0, limit: int = 10`). Type conversion and default values are handled automatically.
4. **Automatic Validation & 422 Errors**:
   - Invalid path/query parameters or JSON body schemas trigger an automatic `422 Unprocessable Entity` JSON response detailing the failing field.
   - *400 vs 422*: `400 Bad Request` indicates syntactically broken HTTP bytes; `422 Unprocessable Entity` indicates syntactically valid HTTP whose payload fails domain/type validation.
5. **Pydantic Request Body Models**:
   - Inheriting from `pydantic.BaseModel` defines expected JSON payloads (`url: str`, `title: str | None = None`).
   - Handles JSON parsing, validation, IDE autocompletion, and schema generation.
6. **Error Responses (`HTTPException`)**:
   - Raising `HTTPException(status_code=404, detail="...")` is caught by FastAPI to automatically construct JSON response payloads `{"detail": "..."}` with correct headers and status line.
7. **Interactive OpenAPI Specs**:
   - Automatically builds an OpenAPI v3 spec at `/openapi.json` from decorators, type annotations, and Pydantic schemas, rendered as Swagger UI at `/docs` and ReDoc at `/redoc`.

### Framework Abstraction Leaks
- **Starlette 405 `Allow` Header Quirk**: Registering the same URL path using separate method decorators (e.g. `@app.get` and `@app.delete`) can cause Starlette's router to emit an incomplete `Allow` header in `405 Method Not Allowed` responses (reporting only the methods of the first route match). Combining route method declarations via `@app.api_route(..., methods=["GET", "DELETE"])` resolves the issue.
